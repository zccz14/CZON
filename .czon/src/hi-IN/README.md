# CZON - AI-नेटिव Markdown कंटेंट इंजन

- **C**: **C**ontent oriented | कंटेंट सर्वोपरि, कंटेंट पर ध्यान केंद्रित
- **Z**: **Z**ero Configuration | ज़ीरो कॉन्फ़िगरेशन लेखन, व्यवधान कम करें
- **O**: **O**rganic AI-Native | जैविक AI-नेटिव, AI का गहरा एकीकरण
- **N**: **N**-shaped Energy Curve | N-आकार की ऊर्जा वक्र, निर्माण-वितरण-प्रतिक्रिया के हर चरण में हस्तक्षेप

AI युग में, एक वेबसाइट कंटेंट क्रिएटर के रूप में, हमारे पास अधिक बुद्धिमान कंटेंट निर्माण इंजन हो सकते हैं।

**कंटेंट की ओर वापसी: व्यवधान को न्यूनतम करें, लेखन पर ध्यान केंद्रित करें**

दस्तावेज़ों को उनके मूल स्वरूप में लौटाएं, लेखन को शांति में लौटाएं।

पहला, मैं पुस्तकालयाध्यक्ष नहीं बनना चाहता। कभी-कभी मैं कुछ सामग्री लिखना चाहता हूं, लेकिन हो सकता है मैंने अभी तक इसका शीर्षक तय न किया हो, या विशेष संगठन न बनाया हो। मैं चाहता हूं कि LLM स्वचालित रूप से मेरी मदद करे शीर्षक जनरेट करने, सारांश बनाने, वर्गीकरण करने, नेविगेशन आदि व्यवस्थित करने का काम।

दूसरा, मेरे अध्ययन कक्ष को साफ-सुथरा रखना होगा। मुझे जटिल कॉन्फ़िगरेशन वाले बिल्ड टूल, पेचीदा दस्तावेज़ कॉन्फ़िगरेशन, जटिल संरचना नहीं चाहिए। हर बार जब मैं Docusaurus, VuePress, Astro जैसे टूल्स के कॉन्फ़िगरेशन फ़ाइलों और प्रोजेक्ट संरचना को देखता हूं, तो मेरा सिर दर्द करने लगता है। अब, CZON ने सभी कॉन्फ़िगरेशन को `.czon` डायरेक्टरी में छिपाकर, कोने में सरका देने का विकल्प चुना है, उपयोगकर्ता को केवल लेखन सामग्री पर ध्यान केंद्रित करने की आवश्यकता है, बाकी सब CZON संभाल लेगा। बाकी सभी डायरेक्टरी आपकी लेखन जगह हैं, आप अपनी Markdown फ़ाइलों को मनचाहे तरीके से व्यवस्थित कर सकते हैं।

**मातृभाषा की ओर वापसी: मातृभाषा में लिखें, बहुभाषी संस्करण सहजता से बनाएं**

जीवन छोटा है, मैं अनुवाद करने में आलसी हूं। व्यक्ति अपनी मातृभाषा का उपयोग करते समय ही अपनी सोच की गहराई का पूरा उपयोग कर सकता है। लेकिन साथ ही दुनिया से जुड़े रहना भी ज़रूरी है, मैं बहुभाषी संवाद को छोड़ना नहीं चाहता। इसलिए मैं एक ऐसे टूल की कामना करता हूं जो मुझे मातृभाषा में लिखने दे, और साथ ही मेरी सामग्री को और अधिक लोगों तक पहुंचाए। वर्तमान i18n में न केवल खुद अनुवाद करना पड़ता है, बल्कि सामग्री अपडेट भी खुद मेंटेन करनी पड़ती है, यह बहुत परेशानी भरा है। मैंने अनुवाद के लिए LLM का उपयोग करने का विकल्प चुना है, इससे मेरा बहुत समय बचता है, और एक क्लिक में कई देशों की भाषाओं में अनुवाद पूरा किया जा सकता है।

## ✨ मुख्य विशेषताएं

1. 🌍 **AI बहुभाषी अनुवाद**: AI का उपयोग करके इंक्रीमेंटल अनुवाद, उपयोगकर्ता मातृभाषा में Markdown लिख सकते हैं, लेकिन उपयोगकर्ता बहुभाषी हो सकते हैं।
2. 📊 **AI मेटाडेटा निष्कर्षण**: शीर्षक, विवरण, सारांश, कीवर्ड, लक्षित पाठक, URL-अनुकूल उपनाम आदि स्वचालित रूप से निकालें।
3. 🏷️ **AI टैग वर्गीकरण**: AI का उपयोग करके सामग्री के लिए टैग और वर्गीकरण का निष्कर्षण और प्रबंधन।
4. 🧭 **AI वर्गीकरण नेविगेशन**: AI का उपयोग करके साइटमैप और नेविगेशन जनरेट करें, स्रोत फ़ाइलों का स्थान संवेदनशील नहीं है।
5. 🤖 **AI पूरी साइट सारांश**: कई शैलियों का उपयोग करके पूरी साइट का सारांश जनरेट किया जा सकता है।

और कुछ गैर-AI विशेषताएं:

1. ⚙️ **ज़ीरो कॉन्फ़िगरेशन**: सभी कॉन्फ़िगरेशन और कैश `.czon` डायरेक्टरी में छिपे हुए हैं, प्रोजेक्ट संरचना साफ-सुथरी रहती है।
2. 🔄 **इंक्रीमेंटल बिल्ड**: कंटेंट हैश के आधार पर परिवर्तनों का पता लगाएं, केवल बदली हुई फ़ाइलों को प्रोसेस करें।
3. 📚 **Markdown एक्सटेंशन समर्थन**: KaTeX गणितीय सूत्र, Mermaid चार्ट, Embla कैरोसेल, फ़ुटनोट आदि के लिए मूल समर्थन।
4. 🚀 **स्टैटिक साइट जनरेशन**: अंतर्निहित React-आधारित SSG, बहुभाषी स्टैटिक साइट जनरेट करता है।
5. 🌐 **विज़िटर की भाषा के आधार पर स्वचालित रूटिंग**: विज़िटर की भाषा के आधार पर स्वचालित रूप से संबंधित भाषा संस्करण पर रूट करें।

## 📦 त्वरित प्रारंभ

### पूर्वापेक्षाएँ

- [Node.js](https://nodejs.org/) इंस्टॉल है (LTS संस्करण 24, या संस्करण 18 और ऊपर का उपयोग करने की सलाह दी जाती है, npx कमांड की आवश्यकता है)
- [OpenAI API Key](https://platform.openai.com/account/api-keys) प्राप्त है, या OPENAI-संगत API Key
- Git इंस्टॉल है (Git से Markdown फ़ाइलों को सूचीबद्ध करने के लिए, .gitignore नियमों द्वारा फ़िल्टर की गई फ़ाइलों को अनदेखा करने के लिए)

### पर्यावरण चर कॉन्फ़िगरेशन

```bash
export OPENAI_API_KEY="sk-xxxxxx"  # आवश्यक: कृपया अपने OpenAI API Key से बदलें
export OPENAI_BASE_URL="https://api.openai.com/v1"  # वैकल्पिक, डिफ़ॉल्ट रूप से OpenAI आधिकारिक API का उपयोग करता है
export OPENAI_MODEL="gpt-3.5-turbo"  # वैकल्पिक, डिफ़ॉल्ट रूप से gpt-3.5-turbo मॉडल का उपयोग करता है
export OPENAI_MAX_TOKENS="4096"  # वैकल्पिक, अधिकतम टोकन सीमा सेट करें (अनदेखा करने पर मॉडल का डिफ़ॉल्ट मान उपयोग होता है, लंबे पाठ अनुवाद के लिए अधिक मान सेट करने की सलाह दी जाती है, जैसे 8192, यह उपयोग किए जा रहे मॉडल द्वारा समर्थित अधिकतम टोकन संख्या पर निर्भर करता है)

# यदि OpenAI API तक पहुंचने के लिए HTTP प्रॉक्सी का उपयोग करने की आवश्यकता है, तो निम्नलिखित चर सेट कर सकते हैं
export HTTPS_PROXY="http://your-proxy.com:8080"  # वैकल्पिक, HTTPS प्रॉक्सी सेट करें
export HTTP_PROXY="http://your-proxy.com:8080"   # वैकल्पिक, HTTP प्रॉक्सी सेट करें
```

### बहुभाषी साइट बनाएं

किसी भी Git-प्रबंधित फ़ोल्डर में चलाएं:

```bash
npx czon@latest build --lang zh-Hans --lang en-US
```

चूंकि भाषा कोड का उपयोग बाद में स्टैटिक साइट जनरेशन में कई कार्यों के हिस्से के रूप में किया जाएगा, कृपया BCP 47 मानक के भाषा कोड का उपयोग करने का ध्यान रखें। उदाहरण के लिए, `zh-Hans` सरलीकृत चीनी का प्रतिनिधित्व करता है, `en-US` अमेरिकी अंग्रेजी का प्रतिनिधित्व करता है। आप आवश्यकतानुसार और भाषाएं जोड़ सकते हैं, जैसे `es-ES` (स्पेनिश) `ja-JP` (जापानी), `ko-KR` (कोरियाई) आदि।
मानक भाषा कोड सूची के लिए कृपया [IETF language tag - Wikipedia](https://en.wikipedia.org/wiki/IETF_language_tag#List_of_common_primary_language_subtags) देखें।

आउटपुट डायरेक्टरी: `.czon/dist`, बाद में इस डायरेक्टरी की सामग्री को स्टैटिक साइट होस्टिंग प्लेटफ़ॉर्म पर डिप्लॉय करने की आवश्यकता होगी।

विस्तृत उपयोग के लिए कृपया `npx czon@latest --help` चलाएं।
