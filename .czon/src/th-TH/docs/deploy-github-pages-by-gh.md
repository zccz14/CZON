# นำไปใช้งานบน GitHub Pages

คู่มือนี้จะอธิบายวิธีการนำเว็บไซต์แบบ Static หลายภาษาที่สร้างโดย CZON ไปใช้งานบน GitHub Pages ผ่าน GitHub CLI

ขั้นแรกให้ติดตั้งเครื่องมือ [GitHub CLI](https://cli.github.com/) (หากยังไม่ได้ติดตั้ง) และตรวจสอบให้แน่ใจว่าได้เข้าสู่ระบบแล้ว (หากยังไม่ได้เข้าสู่ระบบ):

```bash
$ gh --version # ตรวจสอบเวอร์ชัน เพื่อให้แน่ใจว่าติดตั้งสำเร็จ
```

ตรวจสอบให้แน่ใจว่าได้เข้าสู่ระบบแล้ว และมีสิทธิ์การเข้าถึง `repo` ไปยัง repository เป้าหมาย:

```bash
$ gh auth login -s repo # เข้าสู่ระบบบัญชี GitHub จะมีข้อความให้เลือกเข้าสู่ระบบผ่านเบราว์เซอร์หรือใช้ token
$ gh auth status # ตรวจสอบสถานะการเข้าสู่ระบบ ให้แน่ใจว่าเข้าสู่ระบบสำเร็จ และมีสิทธิ์ repo ในการเข้าถึง repository เป้าหมาย
```

ส่วนที่เหลือเพียงแค่รันคำสั่งต่อไปนี้ และทำตามคำแนะนำ:

```bash
$ npx czon@latest config github
```

คำสั่งนี้จะนำคุณผ่านขั้นตอนต่อไปนี้:

1.  ตรวจสอบว่าสิทธิ์ของ gh รวมถึง repo หรือไม่ หากไม่มี จะแจ้งให้เข้าสู่ระบบใหม่และเพิ่มสิทธิ์ repo
2.  หากไดเรกทอรีในเครื่องไม่ใช่ Git repository จะแจ้งให้คุณเริ่มต้น Git repository ใหม่
3.  ตรวจสอบการตั้งค่า remote Git repository ของไดเรกทอรีในเครื่อง ดูว่ามี GitHub remote repository หรือไม่ หากไม่มี GitHub remote repository จะแจ้งให้คุณสร้าง remote repository ใหม่และเพิ่มเป็น remote origin หาก origin มีอยู่แล้วแต่ไม่ใช่ repository ของ GitHub จะแจ้งให้คุณเพิ่ม GitHub remote repository ใหม่เป็น upstream
4.  ตรวจสอบว่า GitHub Pages ถูกเปิดใช้งานและเป็นประเภท workflow หรือไม่ หากไม่ใช่ จะเปิดใช้งานผ่าน API `gh api` และแก้ไขให้เป็นการใช้งานจาก Actions พร้อมทั้งตั้งค่า CNAME (หากคุณมีโดเมนที่กำหนดเอง)
5.  ตรวจสอบไฟล์ GitHub Workflow หากยังไม่ได้สร้าง จะสร้างไฟล์ Pages Workflow หากมีอยู่แล้วแต่ไม่ใช่เวอร์ชันล่าสุด จะแจ้งให้คุณเลือกว่าจะอัปเดตไฟล์ Workflow หรือไม่
6.  commit ไฟล์ Workflow และ push การเปลี่ยนแปลงไปยัง remote repository
7.  แจ้ง URL ของเว็บไซต์ GitHub Pages เพื่อเข้าถึง โดยรับ URL ล่าสุดของ Pages ผ่าน gh api
