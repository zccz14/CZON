# การสร้างรายงานวิเคราะห์ AI - กฎพื้นฐาน

## ขั้นตอนการอ่านเอกสาร (ต้องปฏิบัติตามอย่างเคร่งครัด)

### หลักการสำคัญ

คลังเก็บนี้อาจมีไฟล์ Markdown เป็นร้อยเป็นพันไฟล์ คุณต้อง**อ่านไฟล์แต่ละไฟล์ทีละไฟล์** ห้ามข้ามไฟล์ใดๆ
เพื่อจัดการกับไฟล์จำนวนมาก ให้ใช้กลยุทธ์**การอ่านและสรุปแบบค่อยเป็นค่อยไป**

### ขั้นตอนที่ 1: รับรายชื่อไฟล์ทั้งหมด

1. เรียกใช้ `npx czon@latest ls-files` เพื่อรับไฟล์ Markdown ทั้งหมด
2. บันทึกจำนวนไฟล์ทั้งหมด N
3. บันทึกรายชื่อไฟล์เป็นคิวรอการอ่าน

### ขั้นตอนที่ 2: การอ่านและสรุปเป็นชุด

จัดการไฟล์เป็นชุดๆ ขอแนะนำให้แบ่งชุดละ 10-20 ไฟล์ แต่คุณสามารถปรับเปลี่ยนตามขนาดและความซับซ้อนของไฟล์ได้

**สำหรับแต่ละชุด:**

1.  **อ่าน**: ใช้เครื่องมือ Read เพื่ออ่านเนื้อหาทั้งหมดของแต่ละไฟล์ในชุดนั้นทีละไฟล์
2.  **ดึงข้อมูล**: ดึงข้อมูลที่เกี่ยวข้องตาม**ประเด็นที่สนใจของสไตล์ปัจจุบัน** (ดูคำแนะนำสไตล์ด้านล่าง)
3.  **สรุปชุด**: จัดระเบียบข้อมูลที่ดึงมาจากชุดนั้นเป็นสรุปที่มีโครงสร้าง
4.  **สะสม**: รวมสรุปของชุดเข้ากับ "คลังความรู้" (โครงสร้างคลังความรู้ดูคำแนะนำสไตล์ด้านล่าง)

### ขั้นตอนที่ 3: การจัดการบริบท

เมื่อบริบทใกล้ถึงขีดจำกัด:

1.  **บีบอัดคลังความรู้**: บีบอัดคลังความรู้ตาม**กลยุทธ์การบีบอัดของสไตล์ปัจจุบัน** (ดูคำแนะนำสไตล์ด้านล่าง)
2.  **รักษาดัชนี**: ไม่ว่าจะบีบอัดอย่างไร ต้องรักษาดัชนีพาธและหัวข้อของไฟล์ทั้งหมดไว้
3.  **อ่านต่อ**: ใช้คลังความรู้ที่บีบอัดแล้วเพื่อประมวลผลไฟล์ที่เหลือต่อ

### ขั้นตอนที่ 4: การตรวจสอบความสมบูรณ์

ก่อนสร้างรายงาน ต้องยืนยันว่า:

1.  ไฟล์ทั้งหมด N ไฟล์ในรายชื่อไฟล์ได้รับการประมวลผลแล้ว
2.  คลังความรู้มีข้อมูลพื้นฐานของแต่ละไฟล์ (อย่างน้อยต้องมีพาธและหัวข้อ)

**หากพบว่ามีไฟล์ที่ขาดหายไป**: กลับไปที่ขั้นตอนที่ 2 เพื่อประมวลผลไฟล์ที่ขาดหายไป

### ขั้นตอนที่ 5: การสร้างรายงาน

สามารถเริ่มสร้างรายงานได้ก็ต่อเมื่อ**เสร็จสิ้นทุกขั้นตอนข้างต้นแล้ว**

### พฤติกรรมต้องห้าม

- ❌ ห้ามเริ่มสร้างรายงานก่อนอ่านไฟล์ทั้งหมดเสร็จสิ้น
- ❌ ห้ามข้ามไฟล์ใดๆ ไม่ว่าจำนวนไฟล์จะมากเท่าใด
- ❌ ห้ามอ่านเพียงบางส่วนของไฟล์แล้วอ้างว่า "เข้าใจภาพรวมทั้งหมดแล้ว"
- ❌ ห้ามสร้างไฟล์หรือเนื้อหาที่ไม่มีอยู่จริงในคลังความรู้

## กฎทั่วไป

### 1. หลักการยึดตามข้อเท็จจริง

- จำไว้ว่าต้องยึดตามเนื้อหาข้อเท็จจริง ห้ามมีกรณีที่แยกออกจากข้อเท็จจริง
- ทุกมุมมองต้องมีข้อความต้นฉบับสนับสนุน
- ห้ามสร้างเนื้อหาที่ไม่มีอยู่จริง

### 2. มาตรฐานการอ้างอิงลิงก์

- เมื่ออ้างอิงลิงก์ต้นฉบับ ต้องมั่นใจว่าลิงก์ใช้งานได้
- **ต้องเชื่อมโยงไปยังไฟล์ Markdown เฉพาะเสมอ** ห้ามเชื่อมโยงไปยังไดเรกทอรี
- **ข้อความลิงก์ควรเป็นหัวข้อที่เกี่ยวข้อง** ไม่ใช่ชื่อไฟล์
- เนื่องจากสร้างไปยังไดเรกทอรี SUMMARY ให้ใช้พาธสัมพัทธ์ที่ขึ้นต้นด้วย `../` เมื่ออ้างอิง

**ตัวอย่างที่ถูกต้อง**:

```markdown
[สงครามยืดเยื้อของทุน: กลยุทธ์นักลงทุนรายย่อยก้าวข้ามชนชั้น](../INSIGHTS/6.md)
[จากการสร้างสรรค์สู่การกระจาย – สร้างเครื่องยนต์เนื้อหา AI-Native](../INSIGHTS/4.md)
```

**ตัวอย่างที่ผิด**:

```markdown
[INSIGHTS/6.md](../INSIGHTS/6.md) ← ใช้ชื่อไฟล์แทนหัวข้อ
[สงครามยืดเยื้อของทุน](../INSIGHTS/) ← เชื่อมโยงไปยังไดเรกทอรี
```

### 3. รูปแบบส่วนหัว

แต่ละรายงานต้องเริ่มต้นด้วยรูปแบบต่อไปนี้:

```markdown
# [ชื่อรายงาน]

**เวลาวิเคราะห์ AI**: YYYY-MM-DD
**หมายเหตุ**: รายงานนี้สร้างโดย AI เนื้อหาใช้เพื่อการอ้างอิงเท่านั้น

---
```

### 4. น้ำหนักเวลา

- พิจารณาช่วงเวลา ให้บทความล่าสุดมีน้ำหนักสูงกว่า
- แต่ห้ามละเลยเนื้อหาสำคัญที่เก่ากว่า

### 5. ตำแหน่งการส่งออก

- สร้างรายงานทั้งหมดไปยังไดเรกทอรี `SUMMARY/`
- ตั้งชื่อไฟล์ตามรูปแบบที่กำหนด
