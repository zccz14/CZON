# CZON - AI-Natywny silnik treści Markdown

- **C**: **C**ontent oriented | Zorientowany na treść, skupiony na treści
- **Z**: **Z**ero Configuration | Pisanie bez konfiguracji, minimalizacja zakłóceń
- **O**: **O**rganic AI-Native | Organiczny AI-natywny, głęboko zintegrowany z AI
- **N**: **N**-shaped Energy Curve | Krzywa energii w kształcie N, angażująca się w tworzenie-dystrybucję-feedback na każdym etapie

[> Demo strony](https://czon.zccz14.com/)

W erze AI, jako twórcy treści internetowych, możemy mieć inteligentniejszy silnik tworzenia treści.

**Powrót do treści: minimalizacja zakłóceń, skupienie na pisaniu**

Niech dokumenty wrócą do swojej istoty, niech pisanie wróci do spokoju.

Po pierwsze, nie chcę być bibliotekarzem. Czasami chcę coś napisać, ale może jeszcze nie wymyśliłem tytułu, nie ukształtowałem szczególnej organizacji. Chcę, aby LLM automatycznie generował dla mnie tytuły, tworzył podsumowania, klasyfikował, nawigował i wykonywał inne zadania organizacyjne.

Po drugie, moje biurko musi być czyste. Nie chcę skomplikowanych narzędzi do budowania, nie chcę skomplikowanej konfiguracji dokumentów, nie lubię złożonych struktur. Za każdym razem, gdy widzę pliki konfiguracyjne i struktury projektów takich narzędzi jak Docusaurus, VuePress, Astro, boli mnie głowa. Teraz CZON wybiera ukrycie całej konfiguracji w katalogu .czon, w kącie, użytkownik musi skupić się tylko na pisaniu treści, resztą zajmuje się CZON. Inne katalogi to Twoja przestrzeń do pisania, możesz dowolnie organizować swoje pliki Markdown.

**Powrót do języka ojczystego: pisz w języku ojczystym, płynnie buduj wersje wielojęzyczne**

Życie jest krótkie, nie chce mi się tłumaczyć. Ludzie używając języka ojczystego, mogą w pełni wykorzystać głębię swojego myślenia. Ale jednocześnie utrzymywanie połączenia ze światem jest konieczne, nie chcę rezygnować z komunikacji wielojęzycznej. Dlatego chcę narzędzia, które pozwoli mi pisać w języku ojczystym, a jednocześnie pozwoli większej liczbie osób zobaczyć moje treści. Obecne i18n wymaga nie tylko własnego tłumaczenia, ale także samodzielnego utrzymywania aktualizacji treści, to zbyt uciążliwe. Wybieram użycie LLM do tłumaczenia, oszczędza mi to dużo czasu i pozwala na jednoklikowe tłumaczenie na wiele języków.

## Podstawowe funkcje

1. 🌍 **Automatyczne tłumaczenie wielojęzyczne**: Użyj AI do tłumaczenia przyrostowego, pozwól użytkownikom pisać Markdown w języku ojczystym, ale użytkownicy mogą być wielojęzyczni.
2. 💭 **Automatyczna ekstrakcja podsumowań**: Użyj AI do analizy i ekstrakcji treści z oryginalnego tekstu.
3. 🏷️ **Automatyczna klasyfikacja tagów**: Użyj AI do ekstrakcji i zarządzania tagami i klasyfikacją treści.
4. 🧭 **Inteligentna nawigacja kategorii**: Użyj AI do generowania mapy strony i nawigacji, lokalizacja plików źródłowych nie jest istotna.

## Statyczne generowanie stron (SSG)

CZON ma wbudowane rozwiązanie SSG, które może przekształcić dowolny folder git zawierający Markdown w statyczną stronę HTML.

⚠️ Uwaga: CZON nie jest profesjonalnym generatorem statycznych stron (SSG), ale AI-natywnym silnikiem treści Markdown, skupiającym się na tworzeniu i zarządzaniu treścią.

✅ CZON ma na celu uproszczenie procesu tworzenia i publikowania treści, pozwalając użytkownikom skupić się na samym pisaniu, a nie na skomplikowanej konfiguracji i narzędziach.

❌ CZON nie zapewnia złożonego dostosowywania motywów i ekosystemu wtyczek, ale skupia się na poprawie jakości i dostępności treści poprzez AI.

🔔 Jednak CZON nadal może generować statyczne strony, jeśli to konieczne, CZON może być używany jako preprocesor, integrujący inne rozwiązania SSG do generowania spersonalizowanych, estetycznych stron.

## Szybki start

Wymagania:

- Zainstalowany [Node.js](https://nodejs.org/) (zalecana wersja 18 lub wyższa, wymagane polecenie npx)
- Uzyskany [OpenAI API Key](https://platform.openai.com/account/api-keys), lub kompatybilny klucz API OPENAI
- Zainstalowany Git (do listowania plików Markdown z Git, ignorując pliki filtrowane przez reguły .gitignore)

Najpierw pracuj w folderze zarządzanym przez git:

Skonfiguruj zmienne środowiskowe

```bash
export OPENAI_API_KEY="sk-xxxxxx"  # wymagane: zastąp swoim kluczem API OpenAI
export OPENAI_BASE_URL="https://api.openai.com/v1"  # opcjonalne, domyślnie używa oficjalnego API OpenAI
export OPENAI_MODEL="gpt-3.5-turbo"  # opcjonalne, domyślnie używa modelu gpt-3.5-turbo
export OPENAI_MAX_TOKENS="4096"  # Opcjonalne, ustaw limit maksymalnej liczby tokenów (ignorowanie użyje domyślnej wartości modelu, dla długich tłumaczeń tekstu zaleca się ustawienie wyższej wartości, np. 8192, w zależności od maksymalnej liczby tokenów obsługiwanej przez używany model)
```

Zbuduj stronę, obsługującą tłumaczenie wielojęzyczne. Użyj bieżącego katalogu jako katalogu źródłowego, wyjście do katalogu `.czon/dist`.

- Możesz wielokrotnie używać parametru `--lang` do określenia wersji językowych do wygenerowania (np. `--lang pl-PL --lang en-US`).
- Nie trzeba konfigurować języka źródłowego, CZON wykryje go automatycznie.

```bash
npx czon@latest build --lang pl-PL --lang en-US
```

**Zobacz więcej parametrów lub pomoc**:

```bash
npx czon@latest
```
