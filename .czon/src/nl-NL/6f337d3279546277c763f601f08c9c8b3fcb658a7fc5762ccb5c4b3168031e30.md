# CZON - AI-Native Markdown Content Engine

- **C**: **C**ontent oriented | Inhoud staat centraal, focus op content
- **Z**: **Z**ero Configuration | Zero-configuratie schrijven, minder afleiding
- **O**: **O**rganic AI-Native | Organische AI-native, diepe AI-integratie
- **N**: **N**-shaped Energy Curve | N-vormige energiekromme, betrokken bij alle fasen van creatie-distributie-feedback

[> Website Demo](https://czon.zccz14.com/)

In het AI-tijdperk kunnen we als website-contentmakers een intelligenter contentcreatie-engine hebben.

**Terug naar inhoud: Minimaliseer afleiding, focus op schrijven**

Laat documenten terugkeren naar hun essentie, laat schrijven terugkeren naar rust.

Ten eerste wil ik geen bibliothecaris zijn. Soms wil ik wat inhoud opschrijven, maar ik heb misschien nog geen titel bedacht, nog geen specifieke organisatie gevormd. Ik wil dat LLM automatisch titels voor me genereert, samenvattingen maakt, classificeert, navigeert en andere organisatietaken uitvoert.

Ten tweede moet mijn werkkamer schoon zijn. Ik wil geen complexe bouwtools configureren, geen ingewikkelde documentconfiguraties aanpassen, geen complexe structuren. Elke keer als ik de configuratiebestanden en projectstructuren van tools zoals Docusaurus, VuePress, Astro zie, krijg ik hoofdpijn. Nu kiest CZON ervoor om alle configuratie te verbergen in de .czon-directory, weg te vegen in een hoekje, zodat gebruikers zich alleen hoeven te concentreren op het schrijven van inhoud, en de rest aan CZON overlaten. Alle andere directories zijn uw schrijfruimte, u kunt uw Markdown-bestanden vrij organiseren.

**Terug naar moedertaal: Schrijf in je moedertaal, bouw soepel meertalige versies**

Het leven is kort, ik heb geen zin om te vertalen. Mensen gebruiken hun moedertaal het best om hun denkdiepte te benutten. Maar tegelijkertijd is verbinding met de wereld noodzakelijk, ik wil meertalige communicatie niet opgeven. Daarom wil ik een tool die me in staat stelt in mijn moedertaal te schrijven, terwijl meer mensen mijn inhoud kunnen zien. De huidige i18n vereist niet alleen zelfvertaling, maar ook zelfonderhoud van contentupdates, wat te veel gedoe is. Ik kies ervoor om LLM te gebruiken voor vertalingen, wat me veel tijd bespaart en meertalige vertalingen met één klik mogelijk maakt.

## Basisfuncties

1. 🌍 **Automatische meertalige vertaling**: Gebruik AI voor incrementele vertaling, zodat gebruikers Markdown in hun moedertaal kunnen schrijven, maar meertalig kunnen zijn.
2. 💭 **Automatische samenvattingsextractie**: Gebruik AI voor inhoudsanalyse en -extractie van originele tekst.
3. 🏷️ **Automatische tagclassificatie**: Gebruik AI voor tag- en classificatie-extractie en -beheer van inhoud.
4. 🧭 **Intelligente classificatienavigatie**: Gebruik AI voor sitemap- en navigatiegeneratie, onafhankelijk van bronbestandlocaties.

## Statische Site Generatie (SSG)

CZON heeft een ingebouwd SSG-schema dat elke git-directory met Markdown-bestanden kan omzetten in een statische HTML-site.

⚠️ Let op: CZON is geen professionele statische site generator (SSG), maar een AI-gestuurde Markdown-content engine die zich richt op contentcreatie en -beheer.

✅ CZON is ontworpen om het contentcreatie- en publicatieproces te vereenvoudigen, zodat gebruikers zich kunnen concentreren op het schrijven zelf, in plaats van gehinderd te worden door complexe configuratie en tools.

❌ CZON biedt geen complexe thema-aanpassingen en plug-in ecosystemen, maar richt zich op het verbeteren van contentkwaliteit en toegankelijkheid via AI.

🔔 Maar CZON kan nog steeds statische sites genereren; indien nodig kan CZON worden gebruikt als preprocessor, geïntegreerd met andere SSG-schema's om gepersonaliseerde, mooie sites te genereren.

## Snel starten

Vereisten:

- [Node.js](https://nodejs.org/) geïnstalleerd (aanbevolen versie 18 of hoger, npx-commando nodig)
- [OpenAI API Key](https://platform.openai.com/account/api-keys) verkregen, of OPENAI-compatibele API Key
- Git geïnstalleerd (voor het weergeven van Markdown-bestanden vanuit Git, .gitignore-regels filteren bestanden uit)

Eerst, werk in een directory die al door Git wordt beheerd:

Configureer omgevingsvariabelen

```bash
export OPENAI_API_KEY="sk-xxxxxx"  # Vereist: vervang door uw OpenAI API Key
export OPENAI_BASE_URL="https://api.openai.com/v1"  # Optioneel, standaard gebruikt OpenAI officiële API
export OPENAI_MODEL="gpt-3.5-turbo"  # Optioneel, standaard gebruikt gpt-3.5-turbo model
export OPENAI_MAX_TOKENS="4096"  # Optioneel, stel maximale tokenlimiet in (indien genegeerd gebruikt model standaardwaarde, voor lange tekstvertalingen wordt een hogere waarde aanbevolen, bijvoorbeeld 8192, afhankelijk van maximale tokens die model ondersteunt)
```

Bouw site, ondersteunt meertalige vertaling. Gebruik huidige directory als brondirectory, uitvoer naar `.czon/dist` directory.

- Kan meerdere keren `--lang` parameter gebruiken om gewenste taalversies op te geven (bijvoorbeeld `--lang nl-NL --lang en-US`).
- Bron taal hoeft niet geconfigureerd te worden, CZON detecteert automatisch.

```bash
npx czon@latest build --lang nl-NL --lang en-US
```

**Meer parameters of hulp bekijken**:

```bash
npx czon@latest
```
