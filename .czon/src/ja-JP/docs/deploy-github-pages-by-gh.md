# GitHub Pages へのデプロイ

このガイドでは、GitHub CLI を使用して CZON で生成された多言語静的サイトを GitHub Pages にデプロイする方法を説明します。

まず、[GitHub CLI](https://cli.github.com/) ツールをインストールします（まだインストールしていない場合）。また、ログインしていることを確認してください（まだログインしていない場合）。

```bash
$ gh --version # バージョンを確認し、インストールが成功していることを確認します
```

ログインしていること、およびターゲットリポジトリへの `repo` アクセス権限があることを確認します。

```bash
$ gh auth login -s repo # GitHub アカウントにログインします。ブラウザでのログインまたはトークンを使用したログインを選択するよう促されます。
$ gh auth status # ログイン状態を確認し、正常にログインしており、ターゲットリポジトリへの repo 権限があることを確認します。
```

残りの作業は、以下のコマンドを実行し、プロンプトに従って操作するだけです。

```bash
$ npx czon@latest config github
```

このコマンドは、以下のステップを案内します。

1.  gh の権限に repo が含まれているか確認します。含まれていない場合は、再ログインして repo 権限を追加するよう促します。
2.  ローカルディレクトリが Git リポジトリでない場合、新しい Git リポジトリを初期化するよう促します。
3.  ローカルディレクトリのリモート Git リポジトリ設定を確認し、GitHub リモートリポジトリがあるかどうかを調べます。GitHub リモートリポジトリがない場合は、新しいリモートリポジトリを作成し、それをリモート origin として追加するよう促します。origin がすでに存在するが GitHub リポジトリでない場合は、新しい GitHub リモートリポジトリを upstream として追加するよう促します。
4.  GitHub Pages が有効化されており、workflow タイプであるかどうかを確認します。そうでない場合は、API `gh api` を使用して有効化し、Actions からのデプロイに修正します。また、CNAME を設定します（カスタムドメインをお持ちの場合）。
5.  GitHub Workflow ファイルを確認します。作成されていない場合は、Pages Workflow ファイルを作成します。すでに存在するが最新バージョンでない場合は、Workflow ファイルを更新するかどうかを尋ねます。
6.  Workflow ファイルをコミットし、変更をリモートリポジトリにプッシュします。
7.  GitHub Pages サイトの URL にアクセスするよう促します。`gh api` を使用して最新の Pages URL を取得します。
