# CZON - AI-Native Markdown контентний рушій

- **C**: **C**ontent oriented | Орієнтований на контент, зосереджений на вмісті
- **Z**: **Z**ero Configuration | Нульова конфігурація письма, менше відволікань
- **O**: **O**rganic AI-Native | Органічна AI-нативність, глибока інтеграція AI
- **N**: **N**-shaped Energy Curve | N-подібна крива енергії, втручання в усі етапи: створення-розповсюдження-зворотний зв'язок

[> Демо вебсайту](https://czon.zccz14.com/)

В епоху AI, як автори веб-контенту, ми можемо мати більш розумний рушій для створення контенту.

**Повернення до контенту: мінімізація відволікань, зосередженість на письмі**

Повернути документам їхню сутність, повернути письму спокій.

По-перше, я не хочу бути бібліотекарем. Іноді я хочу щось написати, але можливо ще не визначився з заголовком, ще не сформував чіткої структури. Я хочу, щоб LLM автоматично генерував мені заголовки, робив резюме, класифікував, створював навігацію та інші організаційні завдання.

По-друге, моя робоча зона має бути чистою. Я не хочу складних інструментів збірки, заплутаних конфігурацій документації, не люблю складні структури. Кожного разу, коли я бачу конфігураційні файли та структури проектів таких інструментів, як Docusaurus, VuePress, Astro, у мене болить голова. Зараз CZON вирішив сховати всю конфігурацію в каталог .czon, засунути в кут, щоб користувач міг зосередитися лише на написанні контенту, а решту залишити CZON. Інші каталоги — це ваш простір для письма, ви можете організовувати свої Markdown-файли як завгодно.

**Повернення до рідної мови: пишіть рідною мовою, плавно створюйте багатомовні версії**

Життя коротке, мені ліньки перекладати. Людина найкраще розкриває глибину свого мислення, коли використовує рідну мову. Але одночасно необхідно підтримувати зв'язок зі світом, я не хочу відмовлятися від багатомовного спілкування. Тому я хочу мати інструмент, який дозволить мені писати рідною мовою, але одночасно дозволить більшій кількості людей бачити мій контент. Сучасні i18n вимагають не лише самостійного перекладу, але й самостійного підтримання оновлень контенту, це занадто складно. Я вибираю використання LLM для перекладу, що заощаджує мені багато часу та дозволяє одним кліком завершити переклад на багато мов.

## Основні функції

1. 🌍 **Автоматичний багатомовний переклад**: Використовуйте AI для інкрементного перекладу, дозволяючи користувачам писати Markdown рідною мовою, але користувачі можуть бути багатомовними.
2. 💭 **Автоматичне витягнення резюме**: Використовуйте AI для аналізу та витягнення вмісту з оригінального тексту.
3. 🏷️ **Автоматична класифікація тегів**: Використовуйте AI для витягнення та управління тегами та класифікацією контенту.
4. 🧭 **Інтелектуальна навігація за категоріями**: Використовуйте AI для генерації карти сайту та навігації, розташування вихідних файлів не має значення.

## Генерація статичних сайтів (SSG)

CZON має вбудовану SSG-схему, яка може перетворити будь-яку папку з Markdown-файлами, що керується git, на статичний HTML-сайт.

⚠️ Зверніть увагу, CZON не є професійним генератором статичних сайтів (SSG), а є AI-керованим Markdown контентним рушієм, зосередженим на створенні та управлінні контентом.

✅ CZON спрямований на спрощення процесу створення та публікації контенту, дозволяючи користувачам зосередитися на самому письмі, а не бути обтяженими складною конфігурацією та інструментами.

❌ CZON не надаватиме складну кастомізацію тем та екосистему плагінів, а зосередиться на підвищенні якості та доступності контенту за допомогою AI.

🔔 Однак CZON все ще може генерувати статичні сайти, за необхідності CZON можна використовувати як препроцесор, інтегруючи інші SSG-схеми для створення персоналізованих, красивих сайтів.

## Швидкий старт

Передумови:

- Встановлений [Node.js](https://nodejs.org/) (рекомендована версія 18 та вище, потрібна команда npx)
- Отриманий [OpenAI API Key](https://platform.openai.com/account/api-keys), або сумісний з OPENAI API Key
- Встановлений Git (для отримання списку Markdown-файлів з Git, ігноруючи файли, відфільтровані за правилами .gitignore)

Спочатку працюйте в папці, яка вже керується git:

Налаштування змінних середовища

```bash
export OPENAI_API_KEY="sk-xxxxxx"  # обов'язково: замініть на ваш OpenAI API Key
export OPENAI_BASE_URL="https://api.openai.com/v1"  # опціонально, за замовчуванням використовується офіційний API OpenAI
export OPENAI_MODEL="gpt-3.5-turbo"  # опціонально, за замовчуванням використовується модель gpt-3.5-turbo
export OPENAI_MAX_TOKENS="4096"  # опціонально, встановіть обмеження максимальної кількості токенів (якщо ігнорувати, використовується значення за замовчуванням моделі, для перекладу довгих текстів рекомендується встановити вище значення, наприклад 8192, залежно від максимальної кількості токенів, що підтримується використовуваною моделлю)
```

Збірка сайту з підтримкою багатомовного перекладу. Використовуйте поточний каталог як вихідний, виведення в каталог `.czon/dist`.

- Можна вказати необхідні мовні версії, використовуючи параметр `--lang` кілька разів (наприклад `--lang uk-UA --lang en-US`).
- Не потрібно налаштовувати вихідну мову, CZON визначить її автоматично.

```bash
npx czon@latest build --lang uk-UA --lang en-US
```

**Переглянути більше параметрів або отримати довідку**:

```bash
npx czon@latest
```
