# Генерація AI-аналітичних звітів - Базові правила

## Процес читання документів (має суворо дотримуватися)

### Основні принципи

Це сховище може містити сотні або тисячі файлів Markdown. Ви **повинні прочитати кожен файл послідовно**, не пропускаючи жодного.
Для обробки великої кількості файлів використовується стратегія **поступового читання та підсумкування**.

### Етап 1: Отримання повного списку файлів

1.  Виконайте `npx czon@latest ls-files`, щоб отримати всі файли Markdown
2.  Запишіть загальну кількість файлів N
3.  Збережіть список файлів як чергу для читання

### Етап 2: Порційне читання та підсумкування

Обробляйте файли порціями. Рекомендується розмір порції 10-20 файлів, але ви можете коригувати його самостійно залежно від розміру та складності файлів.

**Для кожної порції:**

1.  **Читання**: Використовуйте інструмент Read, щоб послідовно прочитати повний вміст кожного файлу в порції
2.  **Витягнення**: Витягніть відповідну інформацію на основі **точок фокусу поточного стилю** (див. керівництво зі стилю нижче)
3.  **Підсумок порції**: Упорядкуйте витягнуту інформацію з порції у структурований підсумок
4.  **Накопичення**: Об'єднайте підсумок порції з «База знань» (структура бази знань див. у керівництві зі стилю нижче)

### Етап 3: Управління контекстом

Коли контекст наближається до обмеження:

1.  **Стиснення бази знань**: Стисніть базу знань відповідно до **стратегії стиснення поточного стилю** (див. керівництво зі стилю нижче)
2.  **Збереження індексу**: Незалежно від стиснення, необхідно зберегти індекс шляхів та заголовків усіх файлів
3.  **Продовження читання**: Продовжуйте обробку решти файлів, використовуючи стиснену базу знань

### Етап 4: Перевірка повноти

Перед генерацією звіту необхідно підтвердити:

1.  Усі N файлів зі списку були оброблені
2.  База знань містить базову інформацію про кожен файл (принаймні шлях і заголовок)

**Якщо виявлено пропуски**: Поверніться до етапу 2 для обробки пропущених файлів.

### Етап 5: Генерація звіту

Починати генерацію звіту можна лише після завершення всіх вищезазначених етапів.

### Заборонені дії

-   ❌ Заборонено починати генерацію звіту до завершення читання всіх файлів
-   ❌ Заборонено пропускати будь-які файли, незалежно від їх кількості
-   ❌ Заборонено стверджувати, що «картина повна», прочитавши лише частину файлів
-   ❌ Заборонено вигадувати неіснуючі файли або вміст у базі знань

## Загальні правила

### 1. Принцип фактичної основи

-   Пам'ятайте, що основою мають бути факти, не допускайте відриву від них
-   Усі точки зору мають мати підтримку в оригінальному тексті
-   Заборонено вигадувати неіснуючий вміст

### 2. Стандарти посилань на джерела

-   При посиланні на оригінальне джерело гарантуйте, що посилання дійсне
-   **Завжди посилайтеся на конкретні файли Markdown**, не на директорії
-   **Текст посилання має відповідати заголовку**, а не імені файлу
-   Оскільки генерація відбувається в директорію SUMMARY, використовуйте відносні шляхи, що починаються з `../`

**Правильний приклад**:

```markdown
[Капітальна війна на витривалість: стратегія приватного інвестора для подолання класових бар'єрів](../INSIGHTS/6.md)
[Від створення до поширення — побудова AI-Native контент-двигуна](../INSIGHTS/4.md)
```

**Неправильний приклад**:

```markdown
[INSIGHTS/6.md](../INSIGHTS/6.md) ← використано ім'я файлу замість заголовка
[Капітальна війна на витривалість](../INSIGHTS/) ← посилання веде на директорію
```

### 3. Формат заголовка

Кожен звіт має починатися з наступного формату:

```markdown
# [Заголовок звіту]

**Час AI-аналізу**: РРРР-ММ-ДД
**Примітка**: Цей звіт згенеровано AI, вміст надається лише для довідки.

---
```

### 4. Часова вага

-   Враховуйте часовий проміжок, надаючи більшу вагу останнім статтям
-   Але не ігноруйте важливий ранній вміст

### 5. Місце виведення

-   Усі звіти генеруються в директорію `SUMMARY/`
-   Імена файлів називаються за вказаним форматом
