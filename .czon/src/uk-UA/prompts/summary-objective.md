# Аналітичний звіт у об'єктивно-нейтральному стилі

## Ключові аспекти для читання

Під час читання кожного файлу зосередьтеся на витягуванні:

- Шляху до файлу та його заголовка
- Інформації про дату
- Згаданих назв проєктів та їх функціональних описів
- Згаданих осіб та їхніх ролей
- Об'єктивних фактів та даних
- Конкретної інформації, такої як номери версій, віхи тощо

**Ігноруйте**: суб'єктивні оцінки, емоційні висловлювання, припущення

## Структура бази знань

```
### Індекс файлів
| Шлях до файлу | Заголовок | Дата |
|---------------|-----------|------|

### Індекс проєктів
| Назва проєкту | Опис | Пов'язані файли |
|----------------|------|-----------------|

### Індекс осіб
| Особа | Роль | Пов'язані файли |
|-------|------|-----------------|

### Часова шкала
| Дата | Подія | Джерело (файл) |
|------|-------|----------------|

### Індекс теорій/рамок
| Назва | Основна ідея | Джерело (файл) |
|-------|--------------|----------------|
```

## Стратегія стиснення

Коли потрібно стиснути базу знань:

1. **Обов'язково зберегти**: Індекс файлів (шлях + заголовок), індекс проєктів, індекс осіб
2. **Можна скоротити**: Часову шкалу (зберегти ключові події), індекс теорій (зберегти назви та джерела)
3. **Можна видалити**: Детальні описи, другорядні події

## Визначення стилю

Представляйте інформацію з об'єктивно-нейтральної точки зору, уникайте суб'єктивних оцінок та емоційного забарвлення. Наголошуйте на фактах та даних, забезпечуючи точність та надійність інформації.

**Цільова аудиторія**: Нові читачі, яким потрібно швидко ознайомитися з репозиторієм; потенційні партнери; інвестори
**Тон викладу**: Професійний, стриманий, нейтральний, як при написанні резюме або біографії
**Мета**: Допомогти читачам всебічно зрозуміти основну інформацію та ключові ідеї вмісту, щоб вони могли сформувати власну думку

## Заборонені дії

- ❌ Не додавайте емоційні висловлювання (наприклад, "надихає", "на жаль")
- ❌ Не робіть припущень (наприклад, "можливо", "ймовірно", "мабуть")
- ❌ Не використовуйте слова суб'єктивної оцінки (наприклад, "відмінний", "жахливий", "цікавий")
- ❌ Не оцінюйте, що добре, а що погано
- ❌ Не використовуйте першу особу

## Обов'язкова структура розділів

### Огляд

- Коротка інформація про власника репозиторію (ім'я/ID, статус, основні сфери діяльності)
- Часовий проміжок вмісту репозиторію
- Список основних проєктів (короткий перелік)

### Опис проєкту

Для кожного основного проєкту використовуйте таку структуру:

```markdown
### [Назва проєкту]

- **Походження**: Джерело та контекст проєкту
- **Основні функції**:
  - Функція 1
  - Функція 2
- **Ітерації версій**: Якщо є історія версій, коротко опишіть
- **Пов'язані файли**: [Заголовок статті](../шлях/до/файлу.md)
```

### Ключові теми

Згрупуйте вміст за темами:

```markdown
### 1. [Назва теми]

- [Заголовок статті 1](../шлях/до/файлу1.md): Резюме основної ідеї
- [Заголовок статті 2](../шлях/до/файлу2.md): Резюме основної ідеї
```

### Часова шкала

Використовуйте табличний формат для відображення ключових подій:

```markdown
| Дата       | Ключова подія             |
| ---------- | ------------------------ |
| РРРР-ММ-ДД | Опис події (об'єктивний) |
```

### Основні особи

Використовуйте табличний формат:

```markdown
| Особа    | Роль      | Примітки            |
| -------- | --------- | ------------------- |
| Ім'я/ID | Посада/зв'язок | Пов'язана об'єктивна інформація |
```

### Резюме теоретичних рамок

Для теорій/рамок, запропонованих у репозиторії:

```markdown
### [Назва рамки]

- **Основна ідея**: Короткий опис одним реченням
- **Ключові елементи**: Перелік основних компонентів
- **Математичний вираз**: Якщо є формула, наведіть її
```

## Контрольний список якості

- [ ] Відсутні слова суб'єктивної оцінки
- [ ] Відсутні емоційні висловлювання
- [ ] Усі посилання вказують на конкретні файли
- [ ] Текст посилань відповідає заголовкам статей
- [ ] Включено всі обов'язкові розділи
- [ ] Таблиці часової шкали та осіб мають правильний формат
