# Генерация аналитических отчетов ИИ - Основные правила

## Процесс чтения документов (должен строго соблюдаться)

### Ключевые принципы

Этот репозиторий может содержать сотни или тысячи файлов Markdown. Вы должны **прочитать каждый файл по одному**, не пропуская ни одного.
Для обработки большого количества файлов используется стратегия **постепенного чтения и резюмирования**.

### Этап 1: Получение полного списка файлов

1.  Выполните `npx czon@latest ls-files`, чтобы получить все файлы Markdown
2.  Запишите общее количество файлов N
3.  Сохраните список файлов в виде очереди для чтения

### Этап 2: Пакетное чтение и резюмирование

Обрабатывайте файлы партиями. Рекомендуется 10-20 файлов на партию, но вы можете регулировать это в зависимости от размера и сложности файлов.

**Для каждой партии:**

1.  **Чтение**: Используйте инструмент Read для последовательного чтения полного содержимого каждого файла в партии
2.  **Извлечение**: Извлеките соответствующую информацию в соответствии с **точками внимания текущего стиля** (см. руководство по стилю ниже)
3.  **Резюме партии**: Организуйте извлеченную информацию из партии в структурированное резюме
4.  **Накопление**: Объедините резюме партии в «Базу знаний» (структура базы знаний описана в руководстве по стилю ниже)

### Этап 3: Управление контекстом

Когда контекст приближается к лимиту:

1.  **Сжатие базы знаний**: Сожмите базу знаний в соответствии со **стратегией сжатия текущего стиля** (см. руководство по стилю ниже)
2.  **Сохранение индекса**: Независимо от степени сжатия, необходимо сохранить индексы путей и заголовков для всех файлов
3.  **Продолжение чтения**: Используйте сжатую базу знаний для продолжения обработки оставшихся файлов

### Этап 4: Проверка полноты

Перед генерацией отчета необходимо подтвердить:

1.  Все N файлов из списка были обработаны
2.  База знаний содержит основную информацию о каждом файле (как минимум путь и заголовок)

**Если обнаружены пропуски**: Вернитесь к Этапу 2 для обработки пропущенных файлов.

### Этап 5: Генерация отчета

Только после завершения всех вышеуказанных этапов можно приступать к генерации отчета.

### Запрещенные действия

-   ❌ Нельзя начинать генерацию отчета до прочтения всех файлов
-   ❌ Нельзя пропускать какие-либо файлы, независимо от их количества
-   ❌ Нельзя, прочитав лишь часть файлов, утверждать, что «поняли общую картину»
-   ❌ Нельзя выдумывать несуществующие файлы или содержимое в базе знаний

## Общие правила

### 1. Принцип фактической основы

-   Помните, что необходимо опираться на факты, не допускайте отрыва от фактического содержания
-   Все утверждения должны иметь поддержку в исходном тексте
-   Нельзя выдумывать несуществующее содержание

### 2. Стандарты цитирования ссылок

-   При цитировании ссылок на исходный текст убедитесь, что ссылки действительны
-   **Всегда ссылайтесь на конкретные файлы Markdown**, а не на каталоги
-   **Текст ссылки должен соответствовать заголовку**, а не имени файла
-   Поскольку генерация происходит в каталог SUMMARY, при цитировании используйте относительные пути, начинающиеся с `../`

**Правильный пример**:

```markdown
[Капитальная война на выживание: стратегия личного инвестора по преодолению классового барьера](../INSIGHTS/6.md)
[От создания до распространения — построение AI-Native контент-движка](../INSIGHTS/4.md)
```

**Неправильный пример**:

```markdown
[INSIGHTS/6.md](../INSIGHTS/6.md) ← использовано имя файла вместо заголовка
[Капитальная война на выживание](../INSIGHTS/) ← ссылка ведет на каталог
```

### 3. Формат заголовка

Каждый отчет должен начинаться со следующего формата:

```markdown
# [Заголовок отчета]

**Время анализа ИИ**: ГГГГ.ММ.ДД
**Примечание**: Этот отчет сгенерирован ИИ, содержание носит справочный характер.

---
```

### 4. Временной вес

-   Учитывайте временной промежуток, придавая более свежим статьям больший вес
-   Но не игнорируйте важное содержание более ранних статей

### 5. Место вывода

-   Все отчеты генерируются в каталог `SUMMARY/`
-   Имена файлов формируются в соответствии с указанным форматом
