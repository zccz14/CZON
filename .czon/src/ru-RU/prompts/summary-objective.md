# Аналитический отчет в объективно-нейтральном стиле

## Фокус при чтении

При чтении каждого файла основное внимание уделяйте извлечению:

- Пути к файлу и его заголовка
- Информации о дате
- Упоминаемых названий проектов и описаний их функций
- Упоминаемых лиц и их ролей
- Объективных фактов и данных
- Конкретной информации, такой как номера версий, вехи и т.д.

**Игнорировать**: субъективные оценки, эмоциональные выражения, предположительный контент.

## Структура базы знаний

```
### Индекс файлов
| Путь к файлу | Заголовок | Дата |
|--------------|-----------|------|

### Индекс проектов
| Название проекта | Описание | Связанные файлы |
|------------------|----------|-----------------|

### Индекс персоналий
| Лицо | Роль | Связанные файлы |
|------|------|-----------------|

### Хронология
| Дата | Событие | Исходный файл |
|------|---------|---------------|

### Индекс теорий/методологических рамок
| Название | Ключевая идея | Исходный файл |
|----------|---------------|---------------|
```

## Стратегия сжатия

При необходимости сжатия базы знаний:

1. **Обязательно сохранить**: индекс файлов (путь + заголовок), индекс проектов, индекс персоналий.
2. **Можно сократить**: хронологию (сохранить ключевые узлы), индекс теорий (сохранить названия и источники).
3. **Можно удалить**: подробные описания, второстепенные события.

## Стилистическая позиция

Представляйте информацию с объективно-нейтральной точки зрения, избегая субъективных оценок и эмоциональной окраски. Делайте акцент на фактах и данных, обеспечивая точность и надежность информации.

**Целевая аудитория**: новые читатели, которым необходимо быстро понять общую картину репозитория; потенциальные партнеры; инвесторы.
**Тон изложения**: профессиональный, сдержанный, нейтральный, как при написании резюме или биографии.
**Цель**: помочь читателю всесторонне понять базовую информацию и ключевые идеи содержания, чтобы сформировать собственное суждение.

## Запрещенные действия

- ❌ Не добавлять эмоциональные выражения (например, "вдохновляюще", "к сожалению").
- ❌ Не делать предположений (например, "возможно", "может быть", "вероятно").
- ❌ Не использовать слова субъективной оценки (например, "отличный", "ужасный", "интересный").
- ❌ Не оценивать, что хорошо, а что плохо.
- ❌ Не использовать первое лицо.

## Обязательная структура разделов

### Обзор

- Краткая информация о владельце репозитория (имя/ID, статус, основные области деятельности).
- Временной охват содержания репозитория.
- Список основных проектов (краткое перечисление).

### Описание проекта

Для каждого основного проекта используйте следующую структуру:

```markdown
### [Название проекта]

- **Происхождение**: источник и контекст проекта.
- **Ключевые функции**:
  - Функция 1
  - Функция 2
- **Итерации версий**: если есть история версий, кратко опишите.
- **Связанные файлы**: [Заголовок статьи](../path/to/file.md)
```

### Ключевые темы

Классифицируйте и систематизируйте содержание по темам:

```markdown
### 1. [Название темы]

- [Заголовок статьи 1](../path/to/file1.md): краткое изложение ключевой идеи.
- [Заголовок статьи 2](../path/to/file2.md): краткое изложение ключевой идеи.
```

### Хронология

Используйте табличный формат для отображения ключевых событий:

```markdown
| Дата       | Ключевое событие             |
| ---------- | ---------------------------- |
| ГГГГ-ММ-ДД | Описание события (объективное изложение) |
```

### Основные участники

Используйте табличный формат:

```markdown
| Лицо    | Роль      | Примечания         |
| ------- | --------- | ------------------ |
| Имя/ID  | Должность/Отношение | Связанная объективная информация |
```

### Сводка теоретических/методологических рамок

Для теорий/методологических рамок, представленных в репозитории:

```markdown
### [Название рамки]

- **Ключевая идея**: краткое изложение в одном предложении.
- **Ключевые элементы**: перечислите основные компоненты.
- **Математическое выражение**: если есть формулы, укажите их.
```

## Выходной файл

`SUMMARY/1-objective.md`

## Контрольный список качества

- [ ] Отсутствуют слова субъективной оценки.
- [ ] Отсутствуют эмоциональные выражения.
- [ ] Все ссылки ведут на конкретные файлы.
- [ ] Текст ссылки соответствует заголовку статьи.
- [ ] Включены все обязательные разделы.
- [ ] Таблицы хронологии и участников имеют правильный формат.
