# AI 분석 보고서 생성 - 기본 규칙

## 문서 읽기 프로세스 (반드시 엄격히 준수)

### 핵심 원칙

이 저장소에는 수백, 수천 개의 Markdown 파일이 포함될 수 있습니다. **각 파일을 하나씩 읽어야 하며**, 건너뛰어서는 안 됩니다.
많은 파일을 처리하기 위해 **점진적 읽기 및 요약** 전략을 채택합니다.

### 단계 1: 전체 파일 목록 획득

1. `npx czon@latest ls-files`를 실행하여 모든 Markdown 파일을 가져옵니다.
2. 파일 총 개수 N을 기록합니다.
3. 파일 목록을 읽기 대기열로 저장합니다.

### 단계 2: 분할 읽기 및 요약

파일을 배치로 처리합니다. 배치당 10-20개의 파일을 권장하지만, 파일 크기와 복잡도에 따라 조정할 수 있습니다.

**각 배치에 대해:**

1. **읽기**: Read 도구를 사용하여 해당 배치의 각 파일 전체 내용을 하나씩 읽습니다.
2. **추출**: **현재 스타일의 관심사**(아래 스타일 가이드 참조)에 따라 관련 정보를 추출합니다.
3. **배치 요약**: 해당 배치에서 추출한 정보를 구조화된 요약으로 정리합니다.
4. **누적**: 배치 요약을 '지식 베이스'에 병합합니다(지식 베이스 구조는 아래 스타일 가이드 참조).

### 단계 3: 컨텍스트 관리

컨텍스트가 제한에 가까워지면:

1. **지식 베이스 압축**: **현재 스타일의 압축 전략**(아래 스타일 가이드 참조)에 따라 지식 베이스를 압축합니다.
2. **인덱스 유지**: 어떻게 압축하든, 모든 파일의 경로와 제목 인덱스를 반드시 유지해야 합니다.
3. **읽기 계속**: 압축된 지식 베이스를 사용하여 남은 파일 처리를 계속합니다.

### 단계 4: 완전성 검증

보고서를 생성하기 전에 반드시 확인해야 합니다:

1. 파일 목록의 모든 N개 파일이 처리되었는지
2. 지식 베이스가 각 파일의 기본 정보(최소한 경로와 제목)를 포함하고 있는지

**누락된 파일이 발견되면**: 단계 2로 돌아가 누락된 파일을 처리합니다.

### 단계 5: 보고서 생성

위의 모든 단계를 완료한 후에만 보고서 생성을 시작할 수 있습니다.

### 금지 행위

- ❌ 모든 파일을 읽기 전에 보고서 생성을 시작해서는 안 됩니다.
- ❌ 파일 수에 관계없이 어떤 파일도 건너뛰어서는 안 됩니다.
- ❌ 일부 파일만 읽고 "전체를 파악했다"고 주장해서는 안 됩니다.
- ❌ 지식 베이스에 존재하지 않는 파일이나 내용을 꾸며내서는 안 됩니다.

## 일반 규칙

### 1. 사실 근거 원칙

- 항상 사실 내용을 근거로 해야 하며, 사실과 동떨어진 내용이 나타나서는 안 됩니다.
- 모든 관점은 원문에 근거해야 합니다.
- 존재하지 않는 내용을 꾸며내서는 안 됩니다.

### 2. 인용 링크 규범

- 원문 링크를 인용할 때는 링크가 유효한지 확인합니다.
- **항상 구체적인 Markdown 파일에 링크**해야 하며, 디렉토리에 링크해서는 안 됩니다.
- **링크 텍스트는 해당 제목**이어야 하며, 파일 이름이 아니어야 합니다.
- SUMMARY 디렉토리에 생성되므로, 인용 시 `../`로 시작하는 상대 경로를 사용합니다.

**올바른 예시**:

```markdown
[자본 지속전: 개인 투자자의 계급 초월 전략](../INSIGHTS/6.md)
[창작에서 배포까지——AI-Native 콘텐츠 엔진 구축](../INSIGHTS/4.md)
```

**잘못된 예시**:

```markdown
[INSIGHTS/6.md](../INSIGHTS/6.md) ← 파일 이름을 사용했음 (제목이 아님)
[자본 지속전](../INSIGHTS/) ← 디렉토리에 링크했음
```

### 3. 헤더 형식

각 보고서는 반드시 다음 형식으로 시작해야 합니다:

```markdown
# [보고서 제목]

**AI 분석 시간**: YYYY년 MM월 DD일
**참고**: 본 보고서는 AI가 생성한 내용으로, 참고용입니다.

---
```

### 4. 시간 가중치

- 시간 범위를 고려하여, 최근 글에 더 높은 가중치를 부여합니다.
- 하지만 이전의 중요한 내용을 무시해서는 안 됩니다.

### 5. 출력 위치

- 모든 보고서는 `SUMMARY/` 디렉토리에 생성됩니다.
- 파일 이름은 지정된 형식에 따라 명명됩니다.
