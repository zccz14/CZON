# AI 分析報告生成 - 基礎規則

## 文檔閱讀流程（必須嚴格遵循）

### 核心原則

本倉庫可能包含成百上千個 Markdown 文件。你必須**逐一閱讀每個文件**，不得跳過。
為了處理大量文件，採用**漸進式閱讀與摘要**策略。

### 階段 1：獲取完整文件列表

1.  執行 `npx czon@latest ls-files` 獲取所有 Markdown 文件
2.  記錄文件總數 N
3.  將文件列表保存為待閱讀隊列

### 階段 2：分批閱讀與摘要

將文件分批處理。建議每批 10-20 個文件，但你可以根據文件大小和複雜度自行調整。

**對於每一批：**

1.  **閱讀**：使用 Read 工具逐一讀取該批次的每個文件完整內容
2.  **提取**：根據**當前風格的關注點**（見下方風格指南），提取相關信息
3.  **批次摘要**：將該批次的提取信息整理為結構化摘要
4.  **累積**：將批次摘要合併到「知識庫」中（知識庫結構見下方風格指南）

### 階段 3：上下文管理

當上下文接近限制時：

1.  **壓縮知識庫**：根據**當前風格的壓縮策略**（見下方風格指南）壓縮知識庫
2.  **保留索引**：無論如何壓縮，必須保留所有文件的路徑和標題索引
3.  **繼續閱讀**：使用壓縮後的知識庫繼續處理剩餘文件

### 階段 4：完整性驗證

在生成報告前，必須確認：

1.  文件列表中的所有 N 個文件都已處理
2.  知識庫包含每個文件的基本信息（至少有路徑和標題）

**如果發現遺漏**：返回階段 2 處理遺漏的文件。

### 階段 5：生成報告

只有在完成以上所有階段後，才能開始生成報告。

### 禁止行為

-   ❌ 不得在閱讀完所有文件前開始生成報告
-   ❌ 不得跳過任何文件，無論文件數量多少
-   ❌ 不得僅閱讀部分文件就聲稱"已了解全貌"
-   ❌ 不得在知識庫中虛構不存在的文件或內容

## 通用規則

### 1. 事實依據原則

-   切記以事實內容為依據，不得出現脫離事實的情況
-   所有觀點必須有原文支撐
-   不得虛構不存在的內容

### 2. 引用連結規範

-   引用原文連結時，保證連結有效
-   **永遠連結到具體的 Markdown 文件**，不要連結目錄
-   **連結文字應當是對應的標題**，而不是文件名
-   由於生成到 SUMMARY 目錄，引用時使用 `../` 開頭的相對路徑

**正確範例**：

```markdown
[資本持久戰：個人投資者跨越階級的戰略](../INSIGHTS/6.md)
[從創作到分發——構建AI-Native內容引擎](../INSIGHTS/4.md)
```

**錯誤範例**：

```markdown
[INSIGHTS/6.md](../INSIGHTS/6.md) ← 使用了文件名而非標題
[資本持久戰](../INSIGHTS/) ← 連結到了目錄
```

### 3. 頭部格式

每個報告必須以下列格式開頭：

```markdown
# [報告標題]

**AI 分析時間**：YYYY年MM月DD日
**注**：本報告由 AI 生成，內容僅供參考。

---
```

### 4. 時間權重

-   考慮時間跨度，給予最近的文章更高的權重
-   但不要忽略較早的重要內容

### 5. 輸出位置

-   所有報告生成到 `SUMMARY/` 目錄中
-   文件名按指定格式命名
