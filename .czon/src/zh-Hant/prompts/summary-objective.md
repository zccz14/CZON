# 客觀中立風格分析報告

## 閱讀關注點

閱讀每個檔案時，重點提取：

- 檔案路徑和標題
- 日期資訊
- 涉及的專案名稱和功能描述
- 提到的人物及其角色
- 客觀事實和數據
- 版本號、里程碑等具體資訊

**忽略**：主觀評價、情感表達、推測性內容

## 知識庫結構

```
### 檔案索引
| 檔案路徑 | 標題 | 日期 |
|----------|------|------|

### 專案索引
| 專案名 | 描述 | 相關檔案 |
|--------|------|----------|

### 人物索引
| 人物 | 角色 | 相關檔案 |
|------|------|----------|

### 時間軸
| 日期 | 事件 | 來源檔案 |
|------|------|----------|

### 理論/框架索引
| 名稱 | 核心思想 | 來源檔案 |
|------|----------|----------|
```

## 壓縮策略

當需要壓縮知識庫時：

1. **必須保留**：檔案索引（路徑+標題）、專案索引、人物索引
2. **可以精簡**：時間軸（保留關鍵節點）、理論索引（保留名稱和來源）
3. **可以丟棄**：詳細描述、次要事件

---

## 風格定位

以客觀中立的角度介紹內容，避免主觀評價和情感色彩。強調事實和數據，確保資訊的準確性和可靠性。

**目標讀者**：需要快速了解儲存庫全貌的新讀者、潛在合作者、投資人
**寫作語氣**：專業、克制、中性，如同撰寫履歷或簡歷
**目的**：幫助讀者全面了解內容的基本資訊和核心觀點，形成自己的判斷

## 禁止事項

- ❌ 不要加入情感表達（如「令人振奮」、「遺憾的是」）
- ❌ 不要進行推測（如「可能」、「也許」、「大概」）
- ❌ 不要使用主觀評價詞彙（如「優秀」、「糟糕」、「有趣」）
- ❌ 不要評價好壞優劣
- ❌ 不要使用第一人稱

## 必需章節結構

### 概述

- 儲存庫所有者簡介（姓名/ID、身份、主要領域）
- 儲存庫內容時間跨度
- 主要專案列表（簡要枚舉）

### 專案介紹

對每個主要專案，使用以下結構：

```markdown
### [專案名稱]

- **起源**：專案的來源和背景
- **核心功能**：
  - 功能點 1
  - 功能點 2
- **版本迭代**：如有版本歷史，簡要說明
- **相關檔案**：[文章標題](../path/to/file.md)
```

### 關鍵主題

按主題分類整理內容：

```markdown
### 1. [主題名稱]

- [文章標題1](../path/to/file1.md)：核心觀點摘要
- [文章標題2](../path/to/file2.md)：核心觀點摘要
```

### 時間軸

使用表格格式展示關鍵事件：

```markdown
| 日期       | 關鍵事件             |
| ---------- | -------------------- |
| YYYY-MM-DD | 事件描述（客觀陳述） |
```

### 主要人物

使用表格格式：

```markdown
| 人物    | 角色      | 備註         |
| ------- | --------- | ------------ |
| 姓名/ID | 職位/關係 | 相關客觀資訊 |
```

### 理論框架摘要

對儲存庫中提出的理論/框架：

```markdown
### [框架名稱]

- **核心思想**：一句話概括
- **關鍵要素**：列舉核心組成部分
- **數學表達**：如有公式，列出
```

## 輸出檔案

`SUMMARY/1-objective.md`

## 品質檢查清單

- [ ] 無主觀評價詞彙
- [ ] 無情感表達
- [ ] 所有連結指向具體檔案
- [ ] 連結文字為文章標題
- [ ] 包含所有必需章節
- [ ] 時間軸和人物表格格式正確
