# النشر على GitHub Pages

يشرح هذا الدليل كيفية نشر موقع ثابت متعدد اللغات تم إنشاؤه بواسطة CZON على GitHub Pages باستخدام GitHub CLI.

أولاً، قم بتثبيت أداة [GitHub CLI](https://cli.github.com/) (إذا لم تكن مثبتة بالفعل)، وتأكد من تسجيل الدخول (إذا لم تكن مسجلاً بالفعل):

```bash
$ gh --version # عرض الإصدار، للتأكد من نجاح التثبيت
```

تأكد من تسجيل الدخول، وأن لديك صلاحية `repo` للوصول إلى المستودع المستهدف:

```bash
$ gh auth login -s repo # تسجيل الدخول إلى حساب GitHub، سيُطلب منك اختيار التسجيل عبر المتصفح أو باستخدام رمز token
$ gh auth status # عرض حالة تسجيل الدخول، للتأكد من نجاح التسجيل ووجود صلاحية repo للوصول إلى المستودع المستهدف
```

كل ما تبقى هو تشغيل الأمر التالي واتباع التعليمات:

```bash
$ npx czon@latest config github
```

سيقودك هذا الأمر خلال الخطوات التالية:

1.  التحقق مما إذا كانت صلاحيات gh تتضمن `repo`، إذا لم تكن موجودة، سيتم مطالبتك بتسجيل الدخول مرة أخرى وإضافة صلاحية `repo`.
2.  إذا لم يكن الدليل المحلي مستودع Git، سيتم مطالبتك بتهيئة مستودع Git جديد.
3.  التحقق من إعدادات مستودع Git البعيد للدليل المحلي، والتحقق مما إذا كان هناك مستودع GitHub بعيد. إذا لم يكن هناك مستودع GitHub بعيد، سيتم مطالبتك بإنشاء مستودع بعيد جديد وإضافته كـ `origin`. إذا كان `origin` موجوداً بالفعل ولكنه ليس مستودع GitHub، فسيتم مطالبتك بإضافة مستودع GitHub جديد كـ `upstream`.
4.  التحقق مما إذا كان GitHub Pages مفعلاً، وإذا كان من نوع `workflow`. إذا لم يكن كذلك، سيتم تفعيله عبر API `gh api` وتصحيحه ليتم النشر من خلال Actions. كما سيتم تعيين CNAME (إذا كان لديك نطاق مخصص).
5.  التحقق من ملف GitHub Workflow. إذا لم يكن موجوداً، سيتم إنشاء ملف Workflow لـ Pages؛ إذا كان موجوداً ولكنه ليس أحدث إصدار، سيتم سؤالك عما إذا كنت تريد تحديث ملف Workflow.
6.  إرسال ملف Workflow، ودفع التغييرات إلى المستودع البعيد.
7.  عرض عنوان URL لموقع GitHub Pages، حيث سيتم الحصول على أحدث عنوان URL لـ Pages عبر gh api.
