# CZON - محرك محتوى Markdown الأصلي للذكاء الاصطناعي

- **C**: **م**ركز على **المحتوى** | المحتوى هو الملك، التركيز على المحتوى
- **Z**: **ص**فر إعدادات | الكتابة بدون إعدادات، تقليل الإزعاج
- **O**: **أ**صلي للذكاء الاصطناعي بشكل عضوي | أصلي للذكاء الاصطناعي بشكل عضوي، دمج عميق للذكاء الاصطناعي
- **N**: **م**نحنى الطاقة على شكل N | منحنى الطاقة على شكل N، يتدخل في جميع مراحل الإنشاء-التوزيع-التغذية الراجعة

في عصر الذكاء الاصطناعي، كمنشئي محتوى للمواقع، يمكننا الحصول على محرك إنشاء محتوى أكثر ذكاءً.

**العودة إلى المحتوى: تقليل الإزعاج إلى الحد الأدنى، والتركيز على الكتابة**

دع المستندات تعود إلى جوهرها، دع الكتابة تعود إلى الهدوء.

أولاً، لا أريد أن أكون أمين مكتبة. أحيانًا أريد كتابة بعض المحتوى، لكن قد لا أكون قد فكرت في عنوانه بعد، أو لم أقم بتنظيمه بشكل خاص. أتمنى أن يساعدني نموذج اللغة الكبيرة (LLM) تلقائيًا في إنشاء العناوين، وعمل الملخصات، والتصنيف، والتنقل، وغيرها من مهام التنظيم.

ثانيًا، يجب أن يكون مكتبي نظيفًا. لا أريد أدوات بناء معقدة الإعدادات، أو العبث بتكوينات المستندات المعقدة، ولا أحب الهياكل المعقدة. كلما رأيت ملفات الإعداد وهياكل المشاريع الخاصة بأدوات مثل Docusaurus وVuePress وAstro، أشعر بالصداع. الآن، اختار CZON إخفاء جميع الإعدادات في دليل `.czon`، ودفعها إلى الزاوية، بحيث يحتاج المستخدم فقط إلى التركيز على كتابة المحتوى، ويترك الباقي لـ CZON للتعامل معه. جميع الأدلة الأخرى هي مساحة الكتابة الخاصة بك، يمكنك تنظيم ملفات Markdown الخاصة بك كما تشاء.

**العودة إلى اللغة الأم: الكتابة باللغة الأم، بناء إصدارات متعددة اللغات بسلاسة**

الحياة قصيرة، أنا كسول للترجمة. عندما يستخدم الشخص لغته الأم، يكون قادرًا على استغلال عمق تفكيره إلى أقصى حد. ولكن في نفس الوقت، من الضروري الحفاظ على الاتصال بالعالم، ولا أريد التخلي عن التواصل متعدد اللغات. لذلك، أتمنى أن يكون هناك أداة تسمح لي بالكتابة بلغتي الأم، وفي نفس الوقت تسمح للمزيد من الأشخاص برؤية محتواي. حالياً، يتطلب i18n الترجمة يدويًا، بالإضافة إلى الحفاظ على تحديث المحتوى بنفسك، وهذا مزعج للغاية. أختار استخدام نموذج اللغة الكبيرة (LLM) لمساعدتي في الترجمة، مما يوفر لي الكثير من الوقت، ويمكن إكمال ترجمة لغات متعددة بنقرة واحدة.

## ✨ الميزات الأساسية

1. 🌍 **الترجمة متعددة اللغات بالذكاء الاصطناعي**: استخدام الذكاء الاصطناعي للترجمة التدريجية، مما يسمح للمستخدم بكتابة Markdown بلغته الأم، ولكن يمكن أن يكون المحتوى متعدد اللغات.
2. 📊 **استخراج البيانات الوصفية بالذكاء الاصطناعي**: استخراج العناوين، والوصف، والملخص، والكلمات المفتاحية، والجمهور المستهدف، والأسماء المستعارة الصديقة لـ URL تلقائيًا.
3. 🏷️ **تصنيف الوسوم بالذكاء الاصطناعي**: استخدام الذكاء الاصطناعي لاستخراج وإدارة الوسوم والتصنيفات للمحتوى.
4. 🧭 **التنقل بالتصنيفات باستخدام الذكاء الاصطناعي**: استخدام الذكاء الاصطناعي لإنشاء خريطة الموقع والتنقل، دون حساسية لموقع الملفات المصدر.
5. 🤖 **ملخص الموقع الكامل بالذكاء الاصطناعي**: يمكن إنشاء ملخص للموقع بأكمله بأنماط متعددة.

وبعض الميزات غير المعتمدة على الذكاء الاصطناعي:

1. ⚙️ **صفر إعدادات**: جميع الإعدادات والذاكرة المخبأة مخفية في دليل `.czon`، مما يحافظ على نظافة هيكل المشروع.
2. 🔄 **البناء التدريجي**: اكتشاف التغييرات بناءً على بصمة المحتوى (Hash)، ومعالجة الملفات المتغيرة فقط.
3. 📚 **دعم امتدادات Markdown**: دعم أصلي لصيغ الرياضيات KaTeX، ومخططات Mermaid، وعروض الشرائح Embla، والحواشي السفلية، وغيرها.
4. 🚀 **إنشاء مواقع ثابتة**: يحتوي على مولد مواقع ثابتة (SSG) قائم على React، لإنشاء مواقع ثابتة متعددة اللغات.
5. 🌐 **التوجيه التلقائي بناءً على لغة الزائر**: التوجيه التلقائي إلى إصدار اللغة المناسب بناءً على لغة الزائر.

## 📦 البدء السريع

### المتطلبات الأساسية

- تثبيت [Node.js](https://nodejs.org/) (يُوصى باستخدام الإصدار LTS 24، أو الإصدار 18 فما فوق، مع وجود أمر npx)
- الحصول على [مفتاح OpenAI API](https://platform.openai.com/account/api-keys)، أو مفتاح API متوافق مع OPENAI
- تثبيت Git (لإدراج ملفات Markdown من Git، وتجاهل الملفات التي تمت تصفيتها بواسطة قواعد .gitignore)

### تكوين متغيرات البيئة

```bash
export OPENAI_API_KEY="sk-xxxxxx"  # إلزامي: يرجى استبداله بمفتاح OpenAI API الخاص بك
export OPENAI_BASE_URL="https://api.openai.com/v1"  # اختياري، الافتراضي هو استخدام OpenAI API الرسمي
export OPENAI_MODEL="gpt-3.5-turbo"  # اختياري، الافتراضي هو استخدام نموذج gpt-3.5-turbo
export OPENAI_MAX_TOKENS="4096"  # اختياري، تعيين الحد الأقصى لعدد الرموز (Tokens) (إذا تم تجاهله، سيتم استخدام القيمة الافتراضية للنموذج، للترجمة النصية الطويلة يُوصى بتعيين قيمة أعلى، مثل 8192، اعتمادًا على الحد الأقصى للرموز المدعوم من النموذج المستخدم)

# إذا كنت بحاجة إلى استخدام وكيل HTTP للوصول إلى OpenAI API، يمكنك تعيين المتغيرات التالية
export HTTPS_PROXY="http://your-proxy.com:8080"  # اختياري، تعيين وكيل HTTPS
export HTTP_PROXY="http://your-proxy.com:8080"   # اختياري، تعيين وكيل HTTP
```

### بناء موقع متعدد اللغات

قم بتشغيل الأمر في أي مجلد مُدار بواسطة Git:

```bash
npx czon@latest build --lang zh-Hans --lang en-US
```

نظرًا لأن رموز اللغة ستُستخدم لاحقًا كجزء من العديد من الميزات في إنشاء الموقع الثابت، يرجى التأكد من استخدام رموز اللغة القياسية BCP 47. على سبيل المثال، `zh-Hans` يمثل الصينية المبسطة، و`en-US` يمثل الإنجليزية الأمريكية. يمكنك إضافة المزيد من اللغات حسب الحاجة، مثل `es-ES` (الإسبانية) `ja-JP` (اليابانية)، `ko-KR` (الكورية)، إلخ.
للحصول على قائمة برموز اللغة القياسية، يرجى الرجوع إلى [IETF language tag - Wikipedia](https://en.wikipedia.org/wiki/IETF_language_tag#List_of_common_primary_language_subtags).

دليل الإخراج: `.czon/dist`، ستحتاج لاحقًا إلى نشر محتويات هذا الدليل على منصة استضافة المواقع الثابتة.

للحصول على استخدام مفصل، قم بتشغيل `npx czon@latest --help`.

CZON موقعه هو **محرك محتوى معزز بالذكاء الاصطناعي**، وليس مولد مواقع ثابتة (SSG) كامل الميزات. يركز على تحسين كفاءة إنشاء المحتوى من خلال الذكاء الاصطناعي، وهو مناسب للمبدعين الذين يهتمون بجودة المحتوى ويرغبون في تقليل عبء الإعدادات. في الواقع، يمكن لـ CZON أن يعمل جنبًا إلى جنب مع أدوات SSG مثل Docusaurus وVuePress وAstro، كمحرك أمامي لإنشاء المحتوى وإدارته.
