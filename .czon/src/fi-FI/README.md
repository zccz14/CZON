# CZON - AI-Natiivinen Markdown-sisältömoottori

- **C**: **C**ontent oriented | Sisältö on kuningas, keskittyy sisältöön
- **Z**: **Z**ero Configuration | Nollakonfiguraatiokirjoitus, vähentää häiriöitä
- **O**: **O**rganic AI-Native | Orgaaninen AI-natiivisuus, syvällinen AI-integraatio
- **N**: **N**-shaped Energy Curve | N-muotoinen energiakäyrä, puuttuu luomisen-jakamisen-palautteen kaikkiin vaiheisiin

AI-aikakaudella, verkkosisällöntuottajina, meillä voi olla älykkäämpi sisällönluontimoottori.

**Palaa sisältöön: minimoi häiriöt, keskitty kirjoittamiseen**

Anna dokumenttien palata olemukselleen, anna kirjoittamisen palata rauhaan.

Ensinnäkin, en halua olla kirjastonhoitaja. Haluan joskus kirjoittaa jotain sisältöä, mutta en ehkä ole vielä päättänyt sen otsikosta tai muodostanut erityistä järjestelyä. Toivon, että LLM auttaisi automaattisesti luomaan otsikon, tekemään yhteenvedon, luokittelemaan, navigoimaan ja muita järjestelytehtäviä.

Toiseksi, kirjastoni on siivottava. En halua monimutkaisia rakennustyökaluja, enkä halua säätää monimutkaisten dokumenttien asetusten kanssa, enkä pidä monimutkaisista rakenteista. Aina kun näen Docusaurusin, VuePressin, Astron työkalujen asetustiedostot ja projektirakenteet, minua alkaa särkeä pää. Nyt CZON valitsee piilottaa kaikki asetukset `.czon`-hakemistoon, pyyhkäisee ne nurkkaan, ja käyttäjän tarvitsee keskittyä vain kirjoittamaan sisältöä, loput CZON hoitaa. Muut hakemistot ovat sinun kirjoitustilasi, voit järjestää Markdown-tiedostosi haluamallasi tavalla.

**Palaa äidinkieleen: kirjoita äidinkielellä, luo sujuvasti monikielisiä versioita**

Elämä on lyhyt, en jaksa kääntää. Ihmiset käyttävät parhaiten ajattelunsa syvyyttä äidinkielellään. Mutta yhteydenpito maailmaan on välttämätöntä, en halua luopua monikielisestä viestinnästä. Siksi toivon työkalua, jonka avulla voin kirjoittaa äidinkielelläni ja samalla saada enemmän ihmisiä näkemään sisältöni. Nykyinen i18n vaatii oman käännöksen lisäksi myös sisällön päivitysten ylläpidon, se on liian vaivalloista. Valitsen käyttää LLM:ää auttamaan käännöksissä, säästän paljon aikaa ja voin suorittaa monikielisen käännöksen yhdellä napsautuksella.

## ✨ Ydintoiminnot

1. 🌍 **AI-monikielinen käännös**: Käytä AI:ta lisäyskäännöksiin, anna käyttäjän kirjoittaa Markdown äidinkielellä, mutta käyttäjä voi olla monikielinen.
2. 📊 **AI-metatietojen poiminta**: Poimi automaattisesti otsikko, kuvaus, yhteenveto, avainsanat, kohderyhmä, URL-ystävällinen alias jne.
3. 🏷️ **AI-tunnisteluokittelu**: Käytä AI:ta sisällön tunnisteiden ja luokkien poimintaan ja hallintaan.
4. 🧭 **AI-luokittelunavigointi**: Käytä AI:ta sivustokartan ja navigoinnin luomiseen, lähdetiedostojen sijainti ei ole herkkä.
5. 🤖 **AI-kokosivustoyhteenveto**: Voit luoda kokosivustoyhteenvedon useilla tyyleillä.

Sekä joitain ei-AI-ominaisuuksia:

1. ⚙️ **Nollakonfiguraatio**: Kaikki asetukset ja välimuisti piilotettu `.czon`-hakemistoon, projektirakenne pysyy siistinä.
2. 🔄 **Lisäysrakentaminen**: Perustuu sisällön tiivistetarkistukseen muutosten havaitsemiseksi, käsittelee vain muuttuneet tiedostot.
3. 📚 **Markdown-laajennustuki**: Natiivi tuki KaTeX-matematiikkakaavoille, Mermaid-kaavioille, Embla-karuselleille, alaviitteille jne.
4. 🚀 **Staattinen sivuston luonti**: Sisäänrakennettu React-pohjainen SSG, luo monikielisen staattisen sivuston.
5. 🌐 **Automaattinen reititys kävijän kielen mukaan**: Reitittää automaattisesti kävijän kielen mukaisen kieliversion.

## 📦 Nopea aloitus

### Edellytykset

- Asennettuna [Node.js](https://nodejs.org/) (suositellaan LTS-versiota 24 tai versiota 18 tai uudempaa, tarvitaan npx-komento)
- Haettu [OpenAI API-avain](https://platform.openai.com/account/api-keys) tai OPENAI-yhteensopiva API-avain
- Asennettuna Git (käytetään Markdown-tiedostojen listaukseen Gitistä, ohitetaan .gitignore-sääntöjen suodattamat tiedostot)

### Ympäristömuuttujien määrittäminen

```bash
export OPENAI_API_KEY="sk-xxxxxx"  # Pakollinen: korvaa omalla OpenAI API-avaimellasi
export OPENAI_BASE_URL="https://api.openai.com/v1"  # Valinnainen, käyttää oletuksena OpenAI:n virallista API:a
export OPENAI_MODEL="gpt-3.5-turbo"  # Valinnainen, käyttää oletuksena gpt-3.5-turbo-mallia
export OPENAI_MAX_TOKENS="4096"  # Valinnainen, aseta maksimi token-määräraja (jos jätetään pois, käytetään mallin oletusarvoa, pitkien tekstien käännöksiin suositellaan korkeampaa arvoa, esim. 8192, riippuen käytetyn mallin tukemasta maksimi token-määrästä)

# Jos tarvitset HTTP-välityspalvelinta OpenAI API:n käyttöön, voit asettaa seuraavat muuttujat
export HTTPS_PROXY="http://your-proxy.com:8080"  # Valinnainen, aseta HTTPS-välityspalvelin
export HTTP_PROXY="http://your-proxy.com:8080"   # Valinnainen, aseta HTTP-välityspalvelin
```

### Monikielisen sivuston rakentaminen

Suorita missä tahansa Git-hallinnassa olevassa kansiossa:

```bash
npx czon@latest build --lang zh-Hans --lang en-US
```

Koska kielikoodeja käytetään myöhemmin staattisen sivuston luonnossa monissa toiminnallisuuksissa, varmista, että käytät BCP 47 -standardin mukaisia kielikoodeja. Esimerkiksi `zh-Hans` edustaa yksinkertaistettua kiinaa, `en-US` edustaa amerikanenglantia. Voit lisätä tarvittaessa enemmän kieliä, kuten `es-ES` (espanja) `ja-JP` (japani), `ko-KR` (korea) jne.
Standardikielikoodiluetteloa varten katso [IETF language tag - Wikipedia](https://en.wikipedia.org/wiki/IETF_language_tag#List_of_common_primary_language_subtags).

Tulostushakemisto: `.czon/dist`, tämän hakemiston sisältö on myöhemmin otettava käyttöön staattiselle sivuston isännöintialustalle.

Yksityiskohtaisempi käyttö: suorita `npx czon@latest --help`.

CZON on suunniteltu **AI-tehostetuksi sisältömoottoriksi**, ei täysimittaiseksi SSG:ksi. Se keskittyy sisällönluontitehokkuuden parantamiseen AI:n avulla ja sopii sisällön laadusta huolehtiville luojille, jotka haluavat vähentää konfiguraatiotaakkaa. Itse asiassa CZON:ia voidaan yhdistää Docusauruksen, VuePressin, Astron ja muiden SSG-työkalujen kanssa, toimien sisällön luomisen ja hallinnan etumoottorina.
