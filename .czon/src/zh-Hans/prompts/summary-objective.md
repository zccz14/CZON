# 客观中立风格分析报告

## 阅读关注点

阅读每个文件时，重点提取：

- 文件路径和标题
- 日期信息
- 涉及的项目名称和功能描述
- 提到的人物及其角色
- 客观事实和数据
- 版本号、里程碑等具体信息

**忽略**：主观评价、情感表达、推测性内容

## 知识库结构

```
### 文件索引
| 文件路径 | 标题 | 日期 |
|----------|------|------|

### 项目索引
| 项目名 | 描述 | 相关文件 |
|--------|------|----------|

### 人物索引
| 人物 | 角色 | 相关文件 |
|------|------|----------|

### 时间线
| 日期 | 事件 | 来源文件 |
|------|------|----------|

### 理论/框架索引
| 名称 | 核心思想 | 来源文件 |
|------|----------|----------|
```

## 压缩策略

当需要压缩知识库时：

1. **必须保留**：文件索引（路径+标题）、项目索引、人物索引
2. **可以精简**：时间线（保留关键节点）、理论索引（保留名称和来源）
3. **可以丢弃**：详细描述、次要事件

---

## 风格定位

以客观中立的角度介绍内容，避免主观评价和情感色彩。强调事实和数据，确保信息的准确性和可靠性。

**目标读者**：需要快速了解仓库全貌的新读者、潜在合作者、投资人
**写作语气**：专业、克制、中性，如同撰写简历或履历
**目的**：帮助读者全面了解内容的基本信息和核心观点，形成自己的判断

## 禁止事项

- ❌ 不要加入情感表达（如"令人振奋"、"遗憾的是"）
- ❌ 不要进行推测（如"可能"、"也许"、"大概"）
- ❌ 不要使用主观评价词汇（如"优秀"、"糟糕"、"有趣"）
- ❌ 不要评价好坏优劣
- ❌ 不要使用第一人称

## 必需章节结构

### 概述

- 仓库所有者简介（姓名/ID、身份、主要领域）
- 仓库内容时间跨度
- 主要项目列表（简要枚举）

### 项目介绍

对每个主要项目，使用以下结构：

```markdown
### [项目名称]

- **起源**：项目的来源和背景
- **核心功能**：
  - 功能点 1
  - 功能点 2
- **版本迭代**：如有版本历史，简要说明
- **相关文件**：[文章标题](../path/to/file.md)
```

### 关键主题

按主题分类整理内容：

```markdown
### 1. [主题名称]

- [文章标题1](../path/to/file1.md)：核心观点摘要
- [文章标题2](../path/to/file2.md)：核心观点摘要
```

### 时间线

使用表格格式展示关键事件：

```markdown
| 日期       | 关键事件             |
| ---------- | -------------------- |
| YYYY-MM-DD | 事件描述（客观陈述） |
```

### 主要人物

使用表格格式：

```markdown
| 人物    | 角色      | 备注         |
| ------- | --------- | ------------ |
| 姓名/ID | 职位/关系 | 相关客观信息 |
```

### 理论框架摘要

对仓库中提出的理论/框架：

```markdown
### [框架名称]

- **核心思想**：一句话概括
- **关键要素**：列举核心组成部分
- **数学表达**：如有公式，列出
```

## 输出文件

`SUMMARY/1-objective.md`

## 质量检查清单

- [ ] 无主观评价词汇
- [ ] 无情感表达
- [ ] 所有链接指向具体文件
- [ ] 链接文本为文章标题
- [ ] 包含所有必需章节
- [ ] 时间线和人物表格格式正确
