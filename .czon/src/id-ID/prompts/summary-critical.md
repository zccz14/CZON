# Laporan Analisis Gaya Kritik Objektif

## Fokus Pembacaan

Saat membaca setiap file, fokus untuk mengekstrak:

- Jalur file dan judul
- Pandangan, klaim, atau solusi yang diajukan
- Proses dan dasar argumentasi
- Kondisi dan premis asumsi
- Potensi celah atau kontradiksi logika
- Situasi verifikasi praktis
- Konsistensi/kontradiksi dengan file lain

**Perhatian Khusus**: Pernyataan asertif, penalaran sebab-akibat, kutipan data, premis asumsi

## Struktur Basis Pengetahuan

```
### Indeks File
| Jalur File | Judul | Klaim Utama |
|------------|-------|-------------|

### Indeks Klaim dan Argumentasi
| Klaim | Dasar Argumentasi | Penilaian Kekuatan | File Sumber |
|-------|-------------------|-------------------|-------------|

### Indeks Kondisi Asumsi
| Asumsi | Kelayakan | Klaim Terkait | File Sumber |
|--------|-----------|---------------|-------------|

### Indeks Potensi Masalah
| Jenis Masalah | Deskripsi | Cakupan Dampak | File Sumber |
|---------------|-----------|----------------|-------------|

### Indeks Bukti Keunggulan
| Poin Keunggulan | Bukti | File Sumber |
|-----------------|-------|-------------|

### Catatan Kontradiksi/Ketidakonsistenan
| Konten A | Konten B | Deskripsi Kontradiksi | File Sumber |
|----------|----------|----------------------|-------------|
```

## Strategi Kompresi

Saat perlu mengompresi basis pengetahuan:

1. **Harus Dipertahankan**: Indeks File, Indeks Klaim dan Argumentasi, Indeks Potensi Masalah
2. **Dapat Disederhanakan**: Indeks Kondisi Asumsi (pertahankan asumsi kunci), Bukti Keunggulan (pertahankan kasus tipikal)
3. **Dapat Dibuang**: Deskripsi rinci masalah sekunder

## Penentuan Gaya

Berdasarkan fakta, lakukan analisis kritis objektif terhadap konten, tunjukkan kelebihan dan kekurangannya.

**Pembaca Target**: Pembaca yang ingin mengevaluasi nilai konten secara mendalam, calon kolaborator, pembuat konten itu sendiri
**Nada Penulisan**: Profesional, konstruktif, berdasar
**Tujuan**: Membantu pembaca memahami konten secara lebih komprehensif, mengidentifikasi kelebihan dan kekurangan, mendorong perbaikan

## Prinsip Inti

- ✅ Kritik berdasarkan bukti fakta, bukan dugaan subjektif
- ✅ Kritik bersifat konstruktif, mengajukan saran perbaikan
- ✅ Mengakui kelebihan sambil menunjukkan kekurangan
- ❌ Bukan untuk menyangkal atau merendahkan
- ❌ Tidak melakukan serangan pribadi

## Struktur Bab Wajib

### Ikhtisar

Perkenalkan secara singkat objek analisis dan cakupan analisis

### Evaluasi Desain Arsitektur

- Analisis Kelayakan
- Kecukupan Verifikasi
- Situasi Implementasi Praktis
- **Saran Perbaikan**

### Analisis Investasi/Strategi

- Pemeriksaan Konsistensi Logika
- Tinjauan Kondisi Asumsi
- Identifikasi Risiko
- **Saran Perbaikan**

### Evaluasi Praktik Teknis

- Kelayakan Pemilihan Teknologi
- Kualitas Implementasi
- Kemampuan Pemeliharaan
- **Saran Perbaikan**

### Evaluasi Sistem Teori

- Ketelitian Metodologi
- Cakupan Penerapan
- Keterbatasan
- **Saran Perbaikan**

### Saran Konstruktif Komprehensif

Daftarkan saran perbaikan berdasarkan prioritas:

1. Saran Prioritas Tinggi
2. Saran Prioritas Menengah
3. Saran Jangka Panjang
