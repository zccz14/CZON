# AI 分析报告生成 - 基础规则

## 文档阅读流程（必须严格遵循）

### 核心原则

本仓库可能包含成百上千个 Markdown 文件。你必须**确保每个文件都被处理**，不得跳过。
为了避免文件原文占满上下文窗口，采用**SubAgent 委托阅读**策略：通过 Task 工具将文件分批委托给 SubAgent 读取和提取信息，主 Agent 只接收结构化摘要。

### 阶段 1：获取完整文件列表

1. 执行 `npx czon@latest ls-files` 获取所有 Markdown 文件
2. 记录文件总数 N
3. 将文件列表保存为待阅读队列

### 阶段 2：分批委托 SubAgent 提取信息并写入临时文件

将文件分批处理，每批 10-20 个文件。

**重要**：不要在主 Agent 中直接使用 Read 工具读取 Markdown 源文件内容。必须通过 Task 工具委托 SubAgent 读取源文件，SubAgent 将提取的结构化摘要写入临时文件，以避免文件原文占满主 Agent 的上下文窗口。

**临时文件路径**：见上方「执行任务」中指定的 SubAgent 摘要临时目录，每个批次写入 `batch-{N}.md`（N 为批次编号，从 1 开始）。

**对于每一批：**

1. **构造 SubAgent 任务**：使用 Task 工具启动一个 SubAgent，prompt 中包含：
   - 该批次的文件路径列表
   - 当前风格的关注点和提取要求（从下方风格指南中提炼出具体的提取指令）
   - 指定该批次的输出临时文件路径
   - 要求 SubAgent 逐一使用 Read 工具读取每个源文件，提取结构化信息后使用 Write 工具写入指定的临时文件
2. **并行执行**：多个批次的 Task 应当同时启动（在同一条消息中发出多个 Task 调用），无需等待前一批完成
3. **验证输出**：每个 SubAgent 完成后，**必须检查对应的临时文件是否已生成**（使用 Bash 的 `ls` 或 `stat` 命令）。如果未生成，重新启动该批次的 Task

**SubAgent Prompt 模板**（根据当前风格调整提取要求部分）：

```
请阅读以下 Markdown 文件，为每个文件提取结构化信息，并将结果写入指定的临时文件。

## 提取要求

{从下方风格指南中提炼的具体提取指令，包括该风格关注的维度和字段}

## 文件列表

1. path/to/file1.md
2. path/to/file2.md
...

## 输出要求

将提取结果使用 Write 工具写入文件：{临时文件路径}

格式：对每个文件输出：
- 文件路径
- 文章标题
- {风格特定的提取字段}

请逐一使用 Read 工具读取每个文件的完整内容，提取信息后使用 Write 工具写入指定的临时文件。
**不要返回文件原文**，只写入提取后的结构化摘要。
```

### 阶段 3：验证临时文件完整性

1. **验证文件数量**：检查临时目录下所有批次的 `batch-{N}.md` 文件都已生成
2. **不要立即读取**：此时不要读取临时文件的内容。等到阶段 5 生成报告时，再按需读取对应的临时摘要文件

### 阶段 4：完整性验证

在生成报告前，必须确认：

1. 文件列表中的所有 N 个文件都已处理
2. 知识库包含每个文件的基本信息（至少有路径和标题）

**如果发现遗漏**：返回阶段 2 处理遗漏的文件。

### 阶段 5：生成报告（SubAgent 分章节写入）

只有在完成以上所有阶段后，才能开始生成报告。

**重要**：主 Agent 不要读取任何临时摘要文件的内容。章节内容的填充全部委托给 SubAgent 完成。

#### 步骤 1：写入骨架文件（主 Agent 自己做）

使用 Write 工具创建报告文件，写入以下内容：

- 头部格式（标题、AI 分析时间、文件数量、注释、分隔线）
- 所有章节的标题（仅标题，不含正文）
- 每个章节标题下方放置占位标记：`<!-- SECTION: [章节名] -->`

**示例骨架**：

```markdown
# 报告标题

**AI 分析时间**：2025年01月01日
**基于 42 个 Markdown 文件生成**
**注**：本报告由 AI 生成，内容仅供参考。

---

## 概述

<!-- SECTION: 概述 -->

## 第二章标题

<!-- SECTION: 第二章标题 -->

...
```

#### 步骤 2：委托 SubAgent 逐章节填充

对每个章节，使用 Task 工具启动一个 SubAgent，prompt 中包含：

- 报告文件路径
- 该章节的占位标记（如 `<!-- SECTION: 概述 -->`）
- 临时摘要目录路径（即上方「执行任务」中指定的 SubAgent 摘要临时目录）
- 该章节需要关注的内容方向和写作要求
- 引用链接规范（见下方通用规则）

要求 SubAgent：

1. 读取临时目录下的 batch 文件，获取所需信息
2. 使用 Edit 工具将报告文件中的 `<!-- SECTION: [章节名] -->` 替换为该章节的正文
3. 单次写入不超过 2000 字。如果章节内容超过 2000 字，先写入前半部分并在末尾保留一个临时占位标记（如 `<!-- CONTINUE: [章节名] -->`），再继续写入后半部分

**注意**：各章节的 SubAgent 必须**串行执行**（一个完成后再启动下一个），因为它们都在编辑同一个报告文件，并行会导致冲突。

**SubAgent Prompt 模板**：

```
请为报告文件填充指定章节的内容。

## 任务

1. 读取临时摘要目录 {临时目录路径} 下的所有 batch-*.md 文件
2. 基于摘要内容，为「{章节名}」章节撰写正文
3. 使用 Edit 工具，将报告文件 {报告文件路径} 中的 `<!-- SECTION: {章节名} -->` 替换为章节正文
4. 单次写入不超过 2000 字

## 章节要求

{该章节的具体写作方向和要求}

## 引用链接规范

- 永远链接到具体的 Markdown 文件，不要链接目录
- 链接文本应当是对应的标题，而不是文件名
- 使用 ../../../ 开头的相对路径
- 正确示例：[文章标题](../../../path/to/file.md)
```

#### 步骤 3：完整性检查（主 Agent 自己做）

所有章节 SubAgent 完成后：

1. 使用 Bash 命令 `grep '<!-- SECTION:' {报告文件路径}` 检查是否还有未替换的占位标记
2. 如有遗漏，重新启动对应章节的 SubAgent
3. 确认头部的文件数量 N 正确

### 禁止行为

- ❌ 不得在所有文件处理完成前开始生成报告
- ❌ 不得跳过任何文件，无论文件数量多少
- ❌ 不得仅处理部分文件就声称"已了解全貌"
- ❌ 不得在知识库中虚构不存在的文件或内容
- ❌ 不得在主 Agent 中直接使用 Read 工具读取 Markdown 源文件内容，必须通过 Task SubAgent 读取
- ❌ 不得在主 Agent 中读取临时摘要文件（batch-\*.md）的内容，章节填充必须委托给 SubAgent

---

## 通用规则

### 1. 事实依据原则

- 切记以事实内容为依据，不得出现脱离事实的情况
- 所有观点必须有原文支撑
- 不得虚构不存在的内容

### 2. 引用链接规范

- 引用原文链接时，保证链接有效
- **永远链接到具体的 Markdown 文件**，不要链接目录
- **链接文本应当是对应的标题**，而不是文件名
- 由于生成到 `.czon/AIGC/SUMMARY/` 目录，引用时使用 `../../../` 开头的相对路径

**正确示例**：

```markdown
[资本持久战：个人投资者跨越阶级的战略](../../../INSIGHTS/6.md)
[从创作到分发——构建AI-Native内容引擎](../../../INSIGHTS/4.md)
```

**错误示例**：

```markdown
[INSIGHTS/6.md](../../../INSIGHTS/6.md) ← 使用了文件名而非标题
[资本持久战](../../../INSIGHTS/) ← 链接到了目录
```

### 3. 头部格式

每个报告必须以以下格式开头：

```markdown
# [报告标题]

**AI 分析时间**：YYYY年MM月DD日
**基于 N 个 Markdown 文件生成**
**注**：本报告由 AI 生成，内容仅供参考。

---
```

其中 `N` 为阶段 1 中获取到的实际 Markdown 文件总数。

### 4. 时间权重

- 考虑时间跨度，给予最近的文章更高的权重
- 但不要忽略较早的重要内容
