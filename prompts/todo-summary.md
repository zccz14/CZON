# TODO 待办事项提取报告

## 文档阅读流程（必须严格遵循）

### 核心原则

本仓库可能包含成百上千个 Markdown 文件。你必须**确保每个文件都被处理**，不得跳过。
为了避免文件原文占满上下文窗口，采用**SubAgent 委托阅读**策略：通过 Task 工具将文件分批委托给 SubAgent 读取和提取 TODO 项，主 Agent 只接收结构化的 TODO 条目。

### 阶段 1：获取完整文件列表

1. 执行 `npx czon@latest ls-files` 获取所有 Markdown 文件
2. 记录文件总数 N
3. 将文件列表保存为待阅读队列

### 阶段 2：分批委托 SubAgent 提取 TODO 并写入临时文件

将文件分批处理，每批 10-20 个文件。

**重要**：不要在主 Agent 中直接使用 Read 工具读取 Markdown 源文件内容。必须通过 Task 工具委托 SubAgent 读取源文件，SubAgent 将提取的 TODO 条目写入临时文件，以避免文件原文占满主 Agent 的上下文窗口。

**临时文件路径**：见上方「执行任务」中指定的 SubAgent 摘要临时目录，每个批次写入 `batch-{N}.md`（N 为批次编号，从 1 开始）。

**对于每一批：**

1. **构造 SubAgent 任务**：使用 Task 工具启动一个 SubAgent，prompt 中包含：
   - 该批次的文件路径列表
   - 下方「TODO 提取规则」的完整内容（包括显式 TODO、隐式 TODO、提取要素）
   - 指定该批次的输出临时文件路径
   - 要求 SubAgent 逐一使用 Read 工具读取每个源文件，提取 TODO 项后使用 Write 工具写入指定的临时文件
2. **并行执行**：多个批次的 Task 应当同时启动（在同一条消息中发出多个 Task 调用），无需等待前一批完成
3. **验证输出**：每个 SubAgent 完成后，**必须检查对应的临时文件是否已生成**（使用 Bash 的 `ls` 或 `stat` 命令）。如果未生成，重新启动该批次的 Task

**SubAgent Prompt 模板**：

```
请阅读以下 Markdown 文件，提取所有 TODO 项（显式和隐式），并将结果写入指定的临时文件。

## TODO 提取规则

### 显式 TODO
文中明确表达待办意图的内容，标志词包括：
"TODO"、"FIXME"、"HACK"、"待办"、"待完成"、"待处理"、"待实现"、
"计划做"、"计划实现"、"接下来要做"、"下一步"、"需要实现"、"需要添加"等。

### 隐式 TODO
文中表达了意图或规划但尚未明确完成的事项：
"我会..."、"我打算..."、"我准备..."、"应该..."、"未来会..."、
"还没有..."、描述了功能设想但没有实现迹象等。

## 文件列表

1. path/to/file1.md
2. path/to/file2.md
...

## 输出要求

将提取结果使用 Write 工具写入文件：{临时文件路径}

格式：对每个识别到的 TODO 项输出：
- 描述：TODO 的简短描述（一句话概括）
- 来源文件：文件路径和文章标题
- 原文引用：相关原文片段（1-2 句话）
- 推断日期：该 TODO 提出的日期（从文章内容推断）

如果某个文件中没有 TODO 项，输出：
- 文件路径
- 文章标题
- "无 TODO 项"

请逐一使用 Read 工具读取每个文件的完整内容，提取 TODO 后使用 Write 工具写入指定的临时文件。
**不要返回文件原文**，只写入提取到的 TODO 条目。
```

### 阶段 3：验证临时文件完整性

1. **验证文件数量**：检查临时目录下所有批次的 `batch-{N}.md` 文件都已生成
2. **不要立即读取**：此时不要读取临时文件的内容。等到后续生成报告时，再按需读取对应的临时摘要文件

### 阶段 4：完整性验证

在生成报告前，必须确认：

1. 文件列表中的所有 N 个文件都已处理
2. 所有提取的 TODO 项都有明确的来源文件

**如果发现遗漏**：返回阶段 2 处理遗漏的文件。

## TODO 提取规则

### 显式 TODO

文中明确表达待办意图的内容，包括但不限于以下标志词：

- "TODO"、"FIXME"、"HACK"
- "待办"、"待完成"、"待处理"、"待实现"
- "计划做"、"计划实现"、"计划添加"
- "接下来要做"、"接下来要"、"下一步"
- "需要实现"、"需要添加"、"需要完成"、"需要解决"

### 隐式 TODO

文中表达了意图或规划但尚未明确完成的事项：

- "我会..."、"我打算..."、"我准备..."
- "应该..."、"需要一个..."
- "未来会..."、"之后会..."
- "还没有..."、"暂时没有..."
- 描述了一个功能设想但没有实现的迹象

### 提取要素

对每个识别到的 TODO 项，记录以下信息：

| 字段     | 说明                                 |
| -------- | ------------------------------------ |
| 描述     | TODO 的简短描述（一句话概括）        |
| 来源文件 | 文件路径和文章标题                   |
| 原文引用 | 相关原文片段（1-2 句话）             |
| 推断日期 | 该 TODO 提出的日期（从文章内容推断） |

#### 状态相关的额外提取要素

对于判断为「🔄 进行中」的 TODO，还需额外记录：

| 字段       | 说明                                       |
| ---------- | ------------------------------------------ |
| 已完成部分 | 已经取得的进展（具体做了什么）             |
| 剩余部分   | 尚未完成的内容（还需要做什么）             |
| 进展证据   | 体现进展的后续文章原文片段（注明来源文章） |

对于判断为「✅ 已完成」的 TODO，还需额外记录：

| 字段     | 说明                                       |
| -------- | ------------------------------------------ |
| 完成依据 | 为什么判断已完成（引用具体证据及来源文章） |
| 成果     | 完成后取得了什么具体成果或产出             |

## 状态判断规则

通过交叉对比多篇文章内容，判断每个 TODO 的当前状态：

### ✅ 已完成

- 后续文章中明确提到「已完成」「已实现」「已上线」「已解决」
- 在代码库或产品中可以观察到相关功能已存在
- 相关问题在后续文章中不再被提及，且有明确的解决迹象

### 🔄 进行中

- 后续文章中提到正在做、有部分进展
- 存在相关的中间产物（如设计文档、原型）但未完全完成
- 最近的文章中仍在讨论相关内容

### ⬜ 待开始

- 仅提出了计划或想法，未见任何后续进展
- 没有在其他文章中被再次提及
- 明确标注为未来计划

---

## 优先级标记规则

基于文章内容体现的作者价值观和关注领域，自动判断优先级：

### 🔴 高优先级

- 与核心业务目标直接相关：创业、投资、产品发布、收入目标
- 与正在活跃开发的项目直接相关（如 CZON、CZONE、EA 等）
- 作者在文中明确表达了紧迫感或重要性
- 阻塞其他工作的关键任务

### 🟡 中优先级

- 技术改进、工具优化、流程提升
- 对产品质量有正面影响但非紧急
- 作者表达了兴趣但没有明确时间要求

### 🟢 低优先级

- 探索性想法、研究性质的思考
- 非紧急的改进建议
- 「有空再做」类的想法
- 纯学习或实验目的

## 输出格式

### 头部格式

```markdown
# AI 总结：待办事项

**AI 分析时间**：YYYY年MM月DD日
**基于 N 个 Markdown 文件生成**
**注**：本报告由 AI 自动提取，状态和优先级为 AI 推断结果，仅供参考。

---
```

其中 `N` 为阶段 1 中获取到的实际 Markdown 文件总数。

### 概览

```markdown
## 概览

| 状态      | 数量  |
| --------- | ----- |
| ⬜ 待开始 | X     |
| 🔄 进行中 | X     |
| ✅ 已完成 | X     |
| **总计**  | **X** |
```

### TODO 列表

按状态分组展示，每组内部按优先级排序（高 → 中 → 低）。
不同状态的 TODO 使用不同的展示格式：

#### ⬜ 待开始 格式

```markdown
## ⬜ 待开始

### 🔴 [TODO 简短描述]

- **来源**：[文章标题](../../../path/to/file.md)
- **日期**：YYYY-MM-DD
- **原文**：
  > 引用相关原文片段

---
```

#### 🔄 进行中 格式

```markdown
## 🔄 进行中

### 🔴 [TODO 简短描述]

- **来源**：[文章标题](../../../path/to/file.md)
- **日期**：YYYY-MM-DD
- **原文**：
  > 引用相关原文片段
- **进度**：
  - **已完成**：描述已经取得的进展，具体做了什么
  - **剩余**：描述尚未完成的内容，还需要做什么
  - **证据**：[后续文章标题](../../../path/to/later-file.md)
    > 引用体现进展的后续文章原文片段

---
```

#### ✅ 已完成 格式

```markdown
## ✅ 已完成

### 🔴 [TODO 简短描述]

- **来源**：[文章标题](../../../path/to/file.md)
- **日期**：YYYY-MM-DD
- **原文**：
  > 引用相关原文片段
- **完成依据**：说明为什么判断已完成，引用具体证据
  - 证据来源：[相关文章标题](../../../path/to/evidence-file.md)
- **成果**：描述完成后取得了什么具体成果或产出

---
```

## 引用链接规范

- 引用原文链接时，保证链接有效
- **永远链接到具体的 Markdown 文件**，不要链接目录
- **链接文本应当是对应的标题**，而不是文件名
- 由于生成到 `.czon/AIGC/TODO/` 目录，引用时使用 `../../../` 开头的相对路径

**正确示例**：

```markdown
[资本持久战：个人投资者跨越阶级的战略](../../../INSIGHTS/6.md)
```

**错误示例**：

```markdown
[INSIGHTS/6.md](../../../INSIGHTS/6.md) ← 使用了文件名而非标题
```

## 分段写入规则（SubAgent 分章节写入）

**重要**：主 Agent 不要读取任何临时摘要文件的内容。章节内容的填充全部委托给 SubAgent 完成。

### 步骤 1：写入骨架文件（主 Agent 自己做）

创建报告文件，写入头部、概览占位、各状态章节标题和占位标记。

例如：

```markdown
# AI 总结：待办事项

**AI 分析时间**：YYYY年MM月DD日
**基于 N 个 Markdown 文件生成**
**注**：本报告由 AI 自动提取，状态和优先级为 AI 推断结果，仅供参考。

---

## 概览

<!-- SECTION: 概览 -->

## ⬜ 待开始

<!-- SECTION: 待开始 -->

## 🔄 进行中

<!-- SECTION: 进行中 -->

## ✅ 已完成

<!-- SECTION: 已完成 -->
```

### 步骤 2：委托 SubAgent 逐章节填充

对每个章节，使用 Task 工具启动一个 SubAgent，prompt 中包含：

- 报告文件路径
- 该章节的占位标记（如 `<!-- SECTION: 待开始 -->`）
- 临时摘要目录路径（即上方「执行任务」中指定的 SubAgent 摘要临时目录）
- 该章节需要关注的内容（如：只填充「待开始」状态的 TODO 项）
- 下方的「状态判断规则」「优先级标记规则」和「输出格式」
- 引用链接规范

要求 SubAgent：

1. 读取临时目录下的 batch 文件，获取所有 TODO 条目
2. 根据状态判断规则和优先级标记规则，筛选和排序该章节的 TODO 项
3. 使用 Edit 工具将报告文件中的 `<!-- SECTION: [章节名] -->` 替换为该章节的正文
4. 单次写入不超过 2000 字。如果章节内容超过 2000 字，先写入前半部分并在末尾保留一个临时占位标记（如 `<!-- CONTINUE: [章节名] -->`），再继续写入后半部分

**注意**：各章节的 SubAgent 必须**串行执行**（一个完成后再启动下一个），因为它们都在编辑同一个报告文件，并行会导致冲突。

**SubAgent Prompt 模板**：

```
请为 TODO 报告文件填充指定章节的内容。

## 任务

1. 读取临时摘要目录 {临时目录路径} 下的所有 batch-*.md 文件
2. 从中筛选属于「{章节名}」状态的 TODO 项
3. 按优先级排序（高 → 中 → 低）
4. 使用 Edit 工具，将报告文件 {报告文件路径} 中的 `<!-- SECTION: {章节名} -->` 替换为章节正文
5. 单次写入不超过 2000 字

## 状态判断规则

{复制对应的状态判断规则}

## 优先级标记规则

{复制优先级标记规则}

## 输出格式

{复制对应状态的输出格式模板}

## 引用链接规范

- 永远链接到具体的 Markdown 文件，不要链接目录
- 链接文本应当是对应的标题，而不是文件名
- 使用 ../../../ 开头的相对路径
- 正确示例：[文章标题](../../../path/to/file.md)
```

### 步骤 3：完整性检查（主 Agent 自己做）

所有章节 SubAgent 完成后：

1. 使用 Bash 命令 `grep '<!-- SECTION:' {报告文件路径}` 检查是否还有未替换的占位标记
2. 如有遗漏，重新启动对应章节的 SubAgent
3. 确认概览中的统计数字与实际 TODO 数量一致

---

## 禁止行为

- ❌ 不得在所有文件处理完成前开始生成报告
- ❌ 不得跳过任何文件
- ❌ 不得虚构不存在的 TODO 项
- ❌ 不得虚构完成状态（无法判断时标记为「待开始」）
- ❌ 不得遗漏明确标记的 TODO（如文中出现 "TODO" 字样的条目）
- ❌ 不得在主 Agent 中直接使用 Read 工具读取 Markdown 源文件内容，必须通过 Task SubAgent 读取
- ❌ 不得在主 Agent 中读取临时摘要文件（batch-\*.md）的内容，章节填充必须委托给 SubAgent
